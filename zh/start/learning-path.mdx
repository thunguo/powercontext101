第一次用 PowerContext，不必整站读完。先分清几个对象，再选一条和你现在工作有关的路径。不要同时走几条路，本地 API、Python 框架和 Agent 插件验证的是不同事情。先跑通一条，再决定要不要看下一条。

<Steps titleSize="h3">
  <Step title="先把对象分清" icon="brain">
    从[心智模型总览](/zh/mental-model/overview)开始，再读 [Scope](/zh/mental-model/scope) 和 [fail-open](/zh/mental-model/fail-open)。至少分清 <Tooltip headline="Source" tip="记录发生过什么。采集不会自动写成长期知识。" cta="阅读 Source" href="/zh/mental-model/source">Source</Tooltip>、<Tooltip headline="Memory" tip="经过选择、以后还会用到的项目知识。" cta="阅读 Memory" href="/zh/mental-model/memory">Memory</Tooltip>、<Tooltip headline="PreparedContext" tip="这一次请求用的有界视图。带 Citation，不是长期资产。" cta="阅读心智模型总览" href="/zh/mental-model/overview">PreparedContext</Tooltip> 和 <Tooltip headline="Handoff" tip="把当前目标、已验证进度、阻塞项和下一步交给接手者。不提交就还是临时包。" cta="阅读 Handoff" href="/zh/mental-model/handoff">Handoff</Tooltip>。
  </Step>
  <Step title="启动本地 Server" icon="server">
    按[安装并运行 Server](/zh/basic-usage/install-and-run)做最小配置。只写 Memory、用全文搜索时，不需要推理模型。
  </Step>
  <Step title="只选一条路径" icon="route">
    按下面的目标选一条。先跑通，再看其他框架和 Agent。
  </Step>
  <Step title="需要细节时看官方文档" icon="book-open">
    安装参数、接口说明和部署配置，以 [官方文档](https://oceanbase.github.io/powercontext/) 的最新发布版本为准。101 帮你判断该走哪条路、怎样验证结果。
  </Step>
</Steps>

<Warning>
当前写清的安装路径是 macOS 或 Linux，Python 3.11 及以上。本教程不提供未经验证的 Windows 变通方案。
</Warning>

## 按你的目标选择

<Tabs>
  <Tab title="第一次接触">
    先按这个顺序读：

    1. [心智模型总览](/zh/mental-model/overview)
    2. [Scope](/zh/mental-model/scope)
    3. [fail-open](/zh/mental-model/fail-open)
    4. [安装并运行 Server](/zh/basic-usage/install-and-run)
    5. [常用 API 串讲](/zh/basic-usage/api-tour)

    怎么知道跑通了？按上面第 4、5 步做。先在[安装并运行 Server](/zh/basic-usage/install-and-run) 把本地 Server 拉起来，再打开[常用 API 串讲](/zh/basic-usage/api-tour)，照着脚本写出一条 Memory。

    终端里应能看到三件事：`search_memory` 命中刚才那条；`prepare_context` 返回非空内容；结果里带 Citation。对不上时，先对[排错](/zh/start/troubleshooting)。

    框架、Agent 宿主，以及后面的 Source / Handoff 教程，可以先不看。

    还想多看一点时（可选）：

    对象还容易混，再读 [Source](/zh/mental-model/source)、[Memory](/zh/mental-model/memory)、[Handoff](/zh/mental-model/handoff) 和 [Experience 与 Skill](/zh/mental-model/experience-and-skill)。第一条闭环跑通后，需要时再做 [Source 与 Memory](/zh/basic-usage/source-and-memory)、[Handoff 闭环](/zh/basic-usage/handoff-loop) 和 [Experience / Skill Review](/zh/basic-usage/experience-skill-review)。要用 MCP 客户端连同一套数据，看[用 MCP 连接 Server](/zh/basic-usage/mcp)。要核对同一 Scope 的启用和停用统计，看[用 Dashboard 核对 Scope 统计](/zh/basic-usage/dashboard)。Memory 正文仍通过客户端、HTTP 或 MCP 读取。
  </Tab>
  <Tab title="我写 Python Agent">
    先分清对象，再[安装并运行 Server](/zh/basic-usage/install-and-run)，走完[常用 API 串讲](/zh/basic-usage/api-tour)，然后看[框架集成](/zh/frameworks/overview)。

    怎么知道跑通了？先把[常用 API 串讲](/zh/basic-usage/api-tour) 的脚本跑出三次结果：写入成功、搜索命中、`prepare_context` 带 Citation。再进[框架集成总览](/zh/frameworks/overview)，按 LangGraph 或 LangChain 页把同一条 Memory 接到 Agent 里。新会话还能问到你刚写下的结论，才算接上。

    第一次接入选 LangGraph 或 LangChain，不要先走 Server 推理，也不要先走预览适配器。Pydantic AI Agent 适配器目前是 **Preview**，普通安装路径不可用，不要作为第一次接入。

    如果只要自动找回上下文，Handoff 和 Skill 可以后看。

    还想多看一点时（可选）

    接上 LangGraph 或 LangChain 之后，再看[框架技巧](/zh/frameworks/tricks)。需要 Source 抽取、Handoff 或 Skill 时，走 [Source 与 Memory](/zh/basic-usage/source-and-memory)、[Handoff 闭环](/zh/basic-usage/handoff-loop) 和 [Experience / Skill Review](/zh/basic-usage/experience-skill-review)。Server 推理和预览适配器只在需要时再读。
  </Tab>
  <Tab title="我用 Hermes / OpenClaw">
    先分清对象，再[安装并运行 Server](/zh/basic-usage/install-and-run)，然后看[通用 Agent 总览](/zh/common-agents/overview)，再进 [Hermes](/zh/common-agents/hermes) 或 [OpenClaw](/zh/common-agents/openclaw)。

    怎么知道跑通了？打开对应的 [Hermes](/zh/common-agents/hermes) 或 [OpenClaw](/zh/common-agents/openclaw) 页，按页上的安装和 `powercontext doctor <host>` 做完。`doctor` 通过只说明插件装好了。再开一个新会话，问你刚明确保存的那条 Memory；问得到，才算跑通。

    Hermes 在 `powercontext setup hermes` 后，还要运行 `hermes memory setup` 并选择 PowerContext。OpenClaw 要确认插件占用了 Memory 插槽。WorkBuddy 走独立的 `setup workbuddy` 路径。便携 Agent Plugin 没有安装配置命令；加载它的软件包目录，再验证明确的 MCP 操作。安装、凭证和持久写入仍由你授权。

    还想多看一点时（可选）

    召回跑通后再读 [Handoff](/zh/mental-model/handoff)、[Handoff 闭环](/zh/basic-usage/handoff-loop) 和 [Experience / Skill Review](/zh/basic-usage/experience-skill-review)。[Agent 自扩展](/zh/common-agents/agent-self-extension) 只覆盖托管 Skill 导出。Hermes 和 OpenClaw 导不出去，要换 Codex 或 Claude Code。
  </Tab>
  <Tab title="我用编程 Agent">
    先分清对象，再[安装并运行 Server](/zh/basic-usage/install-and-run)，然后看[编程 Agent 总览](/zh/coding-agents/overview)，再进对应宿主页。

    选择 Codex、Claude Code、DSH、OpenCode 或 Pi。它们连同一套 Server，但生命周期、注入位置和权限确认并不相同。

    怎么知道跑通了？先打开[编程 Agent 总览](/zh/coding-agents/overview) 选宿主，再按那一页的安装和验证做。停掉 Server 后再写一段普通代码，任务还应继续。你明确写入 Memory 或提交 Handoff 失败时，页面或终端里必须能看见错误。各宿主页会用它自己的工具写出这几步。

    还想多看一点时（可选）

    宿主页跑通后再读 [Hook 与插件](/zh/coding-agents/hooks-and-plugins) 和[扩展 Hook](/zh/coding-agents/extend-hooks)。对象细节看 [Source](/zh/mental-model/source)、[Memory](/zh/mental-model/memory)、[Handoff](/zh/mental-model/handoff) 和 [Experience 与 Skill](/zh/mental-model/experience-and-skill)。需要时再跑 [Source 与 Memory](/zh/basic-usage/source-and-memory)、[Handoff 闭环](/zh/basic-usage/handoff-loop) 和 [Experience / Skill Review](/zh/basic-usage/experience-skill-review)。
  </Tab>
  <Tab title="我在写新集成">
    先完成 [Hook 与插件](/zh/coding-agents/hooks-and-plugins)，比较至少两个现有宿主，再读[扩展 Hook](/zh/coding-agents/extend-hooks)。

    要交的不是一段能调用 `prepare_context` 的代码，而是一份能验证的接入说明。Scope、临时注入、Source 采集、权限、诊断、安装和真实宿主端到端验证，都要有明确行为。

    Handoff 和 Skill 教程可以等召回和采集主链稳定后再补。

    还想多看一点时（可选）

    主链稳定后再补 [Source 与 Memory](/zh/basic-usage/source-and-memory)、[Handoff 闭环](/zh/basic-usage/handoff-loop)、[Experience / Skill Review](/zh/basic-usage/experience-skill-review) 和[框架技巧](/zh/frameworks/tricks)。对象页用来对照行为，不是立项门槛：[Source](/zh/mental-model/source)、[Memory](/zh/mental-model/memory)、[Handoff](/zh/mental-model/handoff)、[Experience 与 Skill](/zh/mental-model/experience-and-skill)。
  </Tab>
</Tabs>

## 用同一件事验收

不管选哪条路，都用这件事检查有没有跑通。第一次接触时，在[常用 API 串讲](/zh/basic-usage/api-tour) 里做；接了 Agent 之后，到你选的那一页用它自己的工具重做。

你刚写下一条以后还要用的结论。换一次请求，还能不能找到它？

1. 在固定 Scope 里明确写下来。
2. 换一个请求或新会话再问。
3. 检查召回内容有没有 Citation，并且只进入这一次模型输入。
4. 停掉 Server 再问一次。自动找回可以失败，手头工作还应继续。
5. 再试一次明确写入。失败必须能看见，不能假装保存成功。

不要只在这里打勾。对不上时，先看[排错](/zh/start/troubleshooting)。

<Tip>
自动帮你找回上下文失败时，当前任务还应继续。你明确要求写入 Memory、提交 Handoff、批准或导出时，失败必须能看见。完整说明见 [fail-open](/zh/mental-model/fail-open)。
</Tip>
