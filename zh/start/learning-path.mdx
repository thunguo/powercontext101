第一次使用 PowerContext，不必把整站从头读到尾。先弄清几个对象，再完成一条与你当前工作有关的路径。

<Steps titleSize="h3">
  <Step title="理解对象边界" icon="brain">
    从[心智模型总览](/zh/mental-model/overview)开始，然后读 [Scope](/zh/mental-model/scope) 和 [fail-open](/zh/mental-model/fail-open)。至少要分清 Source、Memory、PreparedContext 和 Handoff。
  </Step>
  <Step title="启动本地 Server" icon="server">
    按[安装并运行 Server](/zh/basic-usage/install-and-run)完成最小配置。显式 Memory 和 FTS 不需要 inference provider。
  </Step>
  <Step title="只选一条路径" icon="route">
    根据下面的工作目标继续。先把一个闭环跑通，再回来看其他框架和宿主。
  </Step>
  <Step title="需要契约时查官方文档" icon="book-open">
    OpenAPI、完整配置、部署和逐项命令属于 [PowerContext 官方文档](https://powercontext.oceanbase.io/)。101 解释为什么这样用，以及如何验证它真的工作。
  </Step>
</Steps>

<Warning>
当前文档化的安装路径是 macOS 或 Linux，Python 版本为 3.11 及以上。本教程不提供未经验证的 Windows 变通方案。
</Warning>

## 按工作目标选择

<Tabs>
  <Tab title="第一次接触">
    阅读顺序：

    1. [心智模型总览](/zh/mental-model/overview)
    2. [Scope](/zh/mental-model/scope)
    3. [fail-open](/zh/mental-model/fail-open)
    4. [安装并运行 Server](/zh/basic-usage/install-and-run)
    5. [常用 API 串讲](/zh/basic-usage/api-tour)

    完成标志：你走完第一条闭环——写入一条 Memory，用 `search_memory` 找到它，再通过 `prepare_context` 得到带 Citation 的 `PreparedContext`。

    可以先跳过框架、宿主，以及后面的 Source / Handoff 页。
  </Tab>
  <Tab title="我写 Python Agent">
    阅读顺序：心智模型 → [安装并运行 Server](/zh/basic-usage/install-and-run) → [常用 API 串讲](/zh/basic-usage/api-tour) → [框架集成](/zh/frameworks/overview)。

    先用 Python Client 跑通 `remember_memory`、`search_memory` 和 `prepare_context`，再进入[框架集成总览](/zh/frameworks/overview)。总览下一步是 LangGraph 或 LangChain，不是 Server inference，也不是 Preview adapter。Pydantic AI Agent adapter 目前是 Preview，普通安装路径不可用，不要把它作为第一次接入。

    如果你只需要自动 recall，可以暂时跳过 Handoff 和 Skill。
  </Tab>
  <Tab title="我用 Hermes / OpenClaw">
    阅读顺序：心智模型 → [安装并运行 Server](/zh/basic-usage/install-and-run) → [通用 Agent 总览](/zh/common-agents/overview) → [Hermes](/zh/common-agents/hermes) 或 [OpenClaw](/zh/common-agents/openclaw)。

    完成标志：宿主插件已安装并激活，`powercontext doctor <host>` 通过，而且新会话能召回你显式保存的 Memory。

    Hermes 在 `powercontext setup hermes` 后还要运行 `hermes memory setup` 并选择 PowerContext。OpenClaw 需要确认插件占用了 memory slot。WorkBuddy 与便携 Agent Plugin 也在这一章：前者单独运行 `setup workbuddy`，后者没有 setup，只验显式 MCP。安装、凭证和持久写入仍受你的授权控制。
  </Tab>
  <Tab title="我用编程 Agent">
    阅读顺序：心智模型 → [安装并运行 Server](/zh/basic-usage/install-and-run) → [编程 Agent 总览](/zh/coding-agents/overview) → 对应宿主页。

    选择 Codex、Claude Code、DSH、OpenCode 或 Pi。它们连接同一个 Server，但 Hook 事件、注入位置、capture、flush 和权限确认并不相同。

    完成标志：自动 recall 失败时普通编码任务仍能继续；显式 Memory 或 Handoff 操作失败时，宿主会把错误告诉你。
  </Tab>
  <Tab title="我在写新集成">
    先完成 [Hook 与插件](/zh/coding-agents/hooks-and-plugins)，再比较至少两个现有宿主，最后阅读[扩展 Hook](/zh/coding-agents/extend-hooks)。

    你的产物不是一段能调用 `/v1/context/prepare` 的代码，而是一份可验证的 adapter contract：Scope、临时注入、Source capture、权限、诊断、安装和 real-host E2E 都有明确行为。

    Basic Usage 的 Handoff 和 Skill 教程可以等到 adapter 的 recall/capture 主链稳定后再补。
  </Tab>
</Tabs>

## 先完成这个检查

无论选择哪条路径，都用同一个简单问题验收：

> 修改 OpenAPI 契约后，下一步应该做什么？

1. 在固定 Scope 中显式保存答案。
2. 换一个请求或新会话提问。
3. 检查召回内容是否带 Citation，并确认它只按该 adapter 的约定进入当前模型输入；是否持久化 message history 由宿主和应用决定。
4. 停止 Server 后再问一次。自动 recall 可以失败，但原任务应继续。
5. 尝试一次显式写入。它必须明确失败，不能假装保存成功。

<Info>
Bub 目前主要由 integration 目录里的 README 说明，101 不为它单独维护路径。它也不在官方 12 个 configure how-to 里。
</Info>
