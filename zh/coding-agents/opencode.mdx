<Warning>
**Version-gated：** OpenCode `>=1.18.21,<2`。超出这个范围的版本属于 **Unsupported**。Package 还要求 Node `>=20`。Conditional real-host E2E 覆盖 `opencode run`，具体边界见下文。
</Warning>

OpenCode 使用 owned native plugin 和 owned bundled `project-context` Skill。`chat.message` 负责 prepare/capture。`experimental.chat.messages.transform` 只在当前 turn 与 cached message 完全匹配时注入 context。

## 成熟度与安装

```bash
powercontext setup opencode --source oceanbase/powercontext --ref master
powercontext server run
powercontext doctor opencode
```

Setup 检查 `opencode --version`，通过 `opencode debug paths` 找到 config directory，并要求 built plugin 和 `skills/project-context/SKILL.md` 都存在。两者分别安装到 `<config>/plugins/powercontext-opencode.js` 和 `<config>/skills/project-context/`，各自带 ownership manifest。

Setup 会预先检查两个目标路径，拒绝 foreign 同名 plugin 或 Skill。单个 installer 有各自的恢复机制，但两个 artifact 之间没有 transaction。如果 plugin 装好后发生 I/O failure，setup 仍可能处于部分完成状态。

Doctor 检查 executable/version、owned Skill 和 plugin activation。Activation probe 会在 loopback 上短暂启动 `opencode serve`，轮询 `GET /session`，等待 plugin 写入 nonce，然后停止进程。它不创建 session、不传 model，也不检查 Server readiness、prompt hooks、injection、permission UI 或 Skill execution。

## 最小用法

Server 启动后，再启动 OpenCode：

```bash
opencode

# Optional checks from another terminal
opencode --version
powercontext doctor opencode
```

之后提交普通 coding prompt。Automatic recall 和符合条件的 prompt capture 不需要命令。需要精确处理 Memory、Handoff、Experience、Skill 或只读 Candidate 时，使用已挂载的 `pc_*` tools。Plugin 不会启动或内嵌 PowerContext Server。

## 执行流程

```text
chat.message(sessionID, messageID)
→ collect non-synthetic text parts
→ resolve the session directory and derive Scope
→ prepare context
→ keep one prepared turn per session, tagged with messageID
→ capture the user prompt independently

experimental.chat.messages.transform
→ find the latest user turn
→ require the same sessionID and exact messageID
→ skip if context is absent or already injected
→ append one synthetic untrusted part for that turn
```

Prepare 先于 capture 执行，但两者分别处理 fail-open。Prepare 失败通常不影响 capture；capture 失败也不会清掉已经有效的 prepared content。不过，两次调用仍共用当前 turn 的 HTTP budget 和已解析的 session context。

`experimental.chat.system.transform` 只添加通用 usage guidance，不负责 PreparedContext injection。

## Scope 与 session cleanup

Scope 按以下顺序解析：

1. 使用 `POWERCONTEXT_OPENCODE_SCOPE_ID`；必要时 hash 成有界 ID。
2. 否则把 session directory 作为派生输入。Explicit tools 使用 `context.worktree || context.directory`。
3. 解析 Git top-level，并尽量把 `remote.origin.url` 规范化成 `git:` Scope。
4. 没有可用 remote 时，把解析后的 project root hash 成稳定的 `local:` Scope。

Directory 或 worktree 是 Scope derivation 的输入，不是优先于 Git identity 的 Scope 结果。

`session.created` 与 `session.updated` 刷新 directory cache。没有 entry 时，plugin 调用 `client.session.get`。`session.deleted` 同时删除该 entry 和当前 session 的 prepared turn。Runtime 每个 session 最多保存一个 prepared turn，而不是保存所有 `(sessionID, messageID)` pair 的 map。

Exact matching 能阻止旧结果注入错误 turn，但仍有 out-of-order race：较早的 prepare 若最后完成，可能覆盖较新的 cache entry。此时新 turn 会漏掉 injection，而不是收到 stale context。Concurrent-turn behavior 为 **Not validated**。

## 注入

PreparedContext 必须符合 `powercontext.prepared-context.v1`，并且 `content_bytes` 与实际内容一致。Configured prepared-content bound 默认为 8,000 bytes，可设置为 512–32,768 bytes。HTTP client 另外把 response body 限制为 1 MiB。

Transform 把 recalled content 标成 host-supplied、untrusted historical evidence，将 part 标为 synthetic，并保留 session/message IDs。第二次 transform 不会重复注入。

`chat.message` 不改写 incoming part，plugin 也不显式写 transcript。Real-host transcript non-persistence 为 **Not validated**；当前 unit evidence 只覆盖 synthetic transform path。

## Capture 与 flush

Capture 排除 synthetic parts，并写入 deterministic prompt Source，metadata 包含 `origin`、event、cwd、session 和 message。Automatic capture 默认开启。关闭 capture、prompt 疑似包含 private key/credential，或 UTF-8 大小超过 200,000 bytes 时，会跳过 capture。

Capture filter 运行前，prepare 已经收到 prompt。因此，疑似包含 secret 的 prompt 仍可能作为 recall query 发往 configured Server，只是不会持久化为 Source。Recall transmission 与 Source capture 是两个独立的隐私决策。

Automatic flush 可选，默认关闭。启用后，正数 capture position 会启动有界 `flush_memory` cursor loop。只有 `current_cursor >= position` 才算成功；error 或 call-budget exhaustion 会 fail-open，也不能证明 Memory 已存在。OpenCode 没有 pending boundary flusher，optional flush path 也没有 OpenCode-specific test，因此 flush E2E 为 **Not validated**。

Automatic path 不 capture final assistant response，也不记录 Task Outcome。

## Owned plugin 与 bundled Skill

Setup 可以刷新 owned install，但会保留 foreign path。Skill conflict path 有直接测试；foreign-plugin conflict 使用同一类实现，不过没有独立的 direct test。

安装后的 `project-context` directory 是 bundled OpenCode Skill，用于告诉宿主何时使用 native plugin tools。它不是 managed Skill export。OpenCode 不是当前 managed export target，real-host Skill discovery 仍为 **Not validated**。

## 原生 tools 与 permission

Plugin 挂载 19 个 curated HTTP tools，覆盖 Memory 读取与 mutation、manual prepare/capture、Handoff activate/prepare/finalize/commit/continue、Experience 和 Skill generate/get，以及 read-only Candidate Review list/get。

它不挂载 Candidate approve/reject/revise、Work Contract creation、Handoff acknowledgement、Task Outcome recording、external-Skill registry 或 Handoff-report operations。Human Candidate mutation 留在 model surface 之外，通过 Dashboard 或受人工控制的 direct API client 完成。

八类指定 mutation——remember、capture Source、revise/retire Memory、activate/commit Handoff、generate Experience、generate Skill——执行前，tool 会用 permission `powercontext` 和 operation ID 调用宿主 `context.ask()`。这个边界是 **Host-gated**。`pc_remember` 的 ask-and-success path 有测试。Ask 被拒绝时，control flow 会在 HTTP 前停止；但真实 UI allow/deny 和 direct denial test 为 **Not validated**。

Explicit mutation payload 若包含疑似 secret 的 nested string，也会在 transport 前被拒绝。这个检查发生在 `context.ask()` 之后，因此宿主可能先 ask，再返回 `secret_rejected`。

## 失败行为

Automatic prepare、capture、injection 和 optional flush 都 fail-open。Server unavailable 或 session context 缺失时，普通 OpenCode 工作不应被阻止。Explicit tool error 对模型保持可见。Configuration error 会发出 warning 并停用 plugin hooks，而不是让宿主崩溃。

## 负向实验

修改 setup 或 plugin 时运行这些实验。这里列的是 deployment checklist，不代表每一项都有 automated test：

- 让 `opencode --version` 返回 `1.18.20` 或 `2.0.0`；setup 应在安装前拒绝。
- 在任一 artifact target 放置 unowned 内容；setup 应保留原内容并拒绝安装。
- 停止 Server，提交 prompt，确认 OpenCode 在没有 recalled context 时仍继续。
- 为一条 message prepare，再 transform 不同的 session 或 message ID；不应注入内容。
- 让两个 prepare 逆序完成；stale context 不应进入新 turn，但新 turn 可能漏掉 injection。
- 对 matching turn 连续 transform 两次；只能有一个 synthetic part。
- 删除 session 后复用旧 IDs；两个 cache 都应为空。
- 提交疑似包含 secret 或超过 200,000-byte 的 prompt；recall 可以运行，capture 不应运行。
- 拒绝指定 mutation，确认没有 HTTP operation 执行。
- 启用 flush，让 cursor 一直落后于 captured position，确认 bounded loop 不会声称 Memory 已存在。
- 检查 model tools，确认 Candidate mutation、Work Contract、acknowledgement 和 Task Outcome operations 都不存在。

## Unsupported 与 Not validated

| State | Current boundary |
|---|---|
| **Supported** | Declared OpenCode gate `>=1.18.21,<2`; owned plugin and bundled-Skill setup; automatic prepare and eligible prompt capture; exact-turn transform logic; curated 19-tool surface; ask-before-classified-mutation control flow; conditional real-host `opencode run` prepare/capture smoke. |
| **Unsupported** | OpenCode `<1.18.21` or `>=2`; overwriting foreign same-name paths; managed Skill export to OpenCode; automatic final-response capture or Task Outcome; model-driven Candidate mutation; the unmounted Work Contract, acknowledgement, Outcome, external-Skill registry, and Handoff-report operations; transactional rollback spanning both installed artifacts. |
| **Not validated** | Compatibility across every accepted release; real-host model dispatch, injection, transcript non-persistence, permission UI, bundled-Skill discovery, cache cleanup, and optional flush; direct upper-version and foreign-plugin tests; reordered concurrent turns; real-host secret and size filtering. |

Conditional real-host E2E 用真实 `opencode run` 启动，使用 invalid model 和 empty PreparedContext，并观察 prepare/capture HTTP requests。它不能证明 model dispatch 或 transform injection。Doctor nonce probe 是另一项 activation check。


## 配置默认值

Plugin 从环境变量读取连接设置。这些默认值决定自动 recall 和 capture 怎么跑：

| Key | 默认值 | 含义 |
|---|---|---|
| `POWERCONTEXT_OPENCODE_BASE_URL` | `http://127.0.0.1:8000` | 正在运行的 PowerContext Server |
| `POWERCONTEXT_OPENCODE_SCOPE_ID` | 未设置 | 显式 Scope；未设置则按仓库推导 |
| `POWERCONTEXT_OPENCODE_AUTHORIZATION` | 未设置 | 完整 Authorization header，含 secret |
| `POWERCONTEXT_OPENCODE_CAPTURE_PROMPTS` | `true` | 采集当前 user prompt 为 Source |
| `POWERCONTEXT_OPENCODE_MAX_BYTES` | `8000` | Recall budget，限制在 `512–32768` |
| `POWERCONTEXT_OPENCODE_REQUEST_TIMEOUT_MS` | `1000` | 单次 HTTP timeout |
| `POWERCONTEXT_OPENCODE_HTTP_BUDGET_MS` | `4000` | 一轮 prepare/capture 总预算 |
| `POWERCONTEXT_OPENCODE_FLUSH_ON_CAPTURE` | `false` | 测试用：capture 后等待 flush |

不要把 Authorization 写进 URL、prompt 或仓库示例。非 loopback 必须用 HTTPS。当前工作不能落成 Source 时，启动前关掉 capture：

```bash
export POWERCONTEXT_OPENCODE_CAPTURE_PROMPTS=false
opencode
```


## 在这个宿主上做完统一题

> 修改 OpenAPI 契约后，下一步应该做什么？

1. 在固定 Scope 里用 `pc_remember` 保存答案。先过 `context.ask`，再确认 Citation。
2. 开一个新 session，再问同一句。
3. 召回必须带 Citation，并且只出现在当前 user turn 的 exact-turn synthetic part，不写进 OpenCode transcript。
4. 停掉 Server 后再问。自动 recall 可以失败，普通编码应继续。删掉旧 session 后，不得再注入 stale context。
5. 再跑 `pc_remember`。Tool 应返回失败，例如 `unavailable`，不能假装写入成功。

- [ ] OpenCode 为 `>=1.18.21,<2`，Node 满足 package 声明的 `>=20`。
- [ ] Setup 安装两个 owned path，并明确说明没有 cross-artifact rollback。
- [ ] Foreign plugin 和 Skill target 会被保留，不会覆盖。
- [ ] `powercontext doctor opencode` 只作为 activation evidence，不当作 Server 或 model-turn test。

- [ ] `chat.message` 排除 synthetic text，先 prepare，再以独立 fail-open handling capture。
- [ ] Transform injection 要求 exact session/message IDs，并保持 idempotent。
