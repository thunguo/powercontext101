description: "比较 first-class 编程宿主，以及 WorkBuddy 与 Agent Plugin 的接入边界。"
---

first-class catalog 里的五个编程宿主连接同一个 PowerContext Server，但没有共用一套 Hook API。共同点是领域合同：解析 Scope、prepare 临时上下文、独立 capture Source，并让显式持久写入经过宿主权限。

官方 configure how-to 另外还有 [WorkBuddy](/zh/coding-agents/workbuddy) 和 [Agent Plugin](/zh/coding-agents/agent-plugin)。前者有独立 `setup` / `doctor`，但不在 `setup select` 里；后者没有 setup 命令，只提供便携 Skill 与 MCP 配置。

## 共同执行流

```text
host event
→ resolve Scope
→ prepare bounded untrusted context
→ inject through host-specific channel
→ run model
→ optionally capture Source / flush
→ explicit tools under host permission
```

## 能力矩阵

| 能力 | Codex | Claude Code | DSH | OpenCode | Pi |
|---|---|---|---|---|---|
| 自动事件 | `UserPromptSubmit` | `UserPromptSubmit` | `agent/pre-step` | `chat.message` + transform | `before_agent_start` |
| 注入 | additional context | `additionalContext` | plugin message | exact-turn message transform | system prompt |
| Prompt capture | 有 | 有 | user-originated batch | 有，过滤 secret-like prompt | 有，过滤 secret/size |
| Final response capture | 无 | 无 | 无 | 无 | 无 |
| 显式接口 | MCP | MCP | native HTTP tools | native HTTP tools | native tools + `/pc` |
| Handoff | MCP + Skill | MCP + Skill | curated HTTP tools | curated HTTP tools | native tools |
| Permission | Host-gated | Host-gated | pre-execute `ask` | `context.ask` | interactive confirm；无 UI 拒绝 |
| Managed Skill export | Supported | Supported | Unsupported | Unsupported | Unsupported |
| Real-host E2E | Not validated | Not validated | Not validated | Supported | package load only；full chain Not validated |

Bundled `project-context` Skill 只是 integration 自带说明，不代表 managed Skill export。

## WorkBuddy 与 Agent Plugin

| 能力 | WorkBuddy | Agent Plugin |
|---|---|---|
| 自动事件 | `UserPromptSubmit` | 无 |
| 注入 | `additionalContext` | 无；只靠 MCP |
| Prompt capture | 有 | 无 |
| 显式接口 | MCP | MCP |
| Handoff | MCP + Skill | MCP + Skill |
| Permission | Host-gated | Host-gated |
| Managed Skill export | Unsupported | Unsupported |
| Real-host E2E | Not validated（仅 service-chain） | Not validated（仅 package contract） |
| Catalog | 独立 `setup` / `doctor`；不在 first-class | 无 setup / doctor |

不要把 WorkBuddy 写成 `setup select` 成员，也不要把 Agent Plugin 写成会自动 prepare 的宿主。

## Setup 与 doctor

```bash
powercontext setup <host> \
  --source oceanbase/powercontext \
  --ref master

powercontext doctor <host>
```

Setup 不启动 Server。Doctor 检查安装/激活的有限边界，不等于 E2E，也不证明真实 recall、permission UI 或跨会话行为。每个宿主页会写明它具体检查什么。

## 自动与显式路径

Automatic recall/capture 属于辅助路径，Server failure 时通常 fail-open。显式 Memory、Handoff、Review 或 export 不能假装成功。

不同宿主的 permission 也不能互相类推：Pi 明确在无 UI 时拒绝 durable write；DSH 和 OpenCode 交给宿主 permission API；Codex/Claude Code 的无 UI 拒绝行为当前 **Not validated**。

## 选择路径

- 需要 Hook + MCP + project Skill：Codex 或 Claude Code。
- 需要 pre-step 与可裁剪 HTTP tools：DSH。
- 需要 exact-turn transient cache 与真实 host E2E：OpenCode。
- 需要 boundary flush 和 no-UI fail-closed：Pi。
- 需要 Codex 同类 Hook + MCP，但宿主是 WorkBuddy：WorkBuddy。单独运行 `setup workbuddy`。
- 需要便携 Skill + MCP、不要宿主专用集成：Agent Plugin。

先读 [Hooks 与插件](/zh/coding-agents/hooks-and-plugins)，再进入对应宿主页。
