<Warning>
这是早期 native integration。Plugin package version 是 `0.0.2`，但 DSH 尚无正式最低 host version。完整的真实 `dsh web` host-process/model E2E 为 **Not validated**。
</Warning>

DSH 使用宿主原生 Hook，不是 MCP plugin。自动 recall/capture 在 `agent/pre-step` 运行；curated `pc_*` tools 直接调用 PowerContext HTTP API。

## 安装与成熟度

```bash
powercontext setup dsh --source oceanbase/powercontext --ref master
powercontext server run
powercontext doctor dsh
```

Setup 要求 `dsh` 位于 `PATH`，并且 built plugin entrypoint `lib/index.js` 已存在。它通过 `dsh plugin --profile web add` 安装 plugin directory。Doctor 读取 `dsh --profile web --dump-config`，查找 exact plugin ID `powercontext-dsh`。Plugin 需要 Node.js 20 或更高版本。

这个检查只能证明配置存在，不能证明真实 turn 已跑通。它不会证明 `dsh web` 已加载 plugin、触发 Hook 或显示 permission prompt。Node.js 要求和开发环境中的 Cordis dependency 都不是正式最低 DSH host version。

## 最小用法

Server 启动后，再启动宿主：

```bash
dsh web

# Run inside DSH
/pc doctor
/pc search authentication decisions
/pc remember Prefer contract tests before refactors
/pc flush
/pc review
```

通常不需要手动 recall，照常发送 prompt 即可。用 `/pc` 查看 Scope 和 endpoint；需要区分 plugin configuration 与 Server health 时，再用 `/pc doctor`。人工命令还覆盖 search、remember、flush 与 Candidate review。Agent 则会收到 curated `pc_*` tools。

## 执行流程

```text
agent/pre-step
→ collect text from every message into the recall query
→ collect user-originated text into capture content
→ resolve workspace Scope
→ prepare context and capture Source independently
→ await next() exactly once
→ inspect the downstream decision
→ if kind is enter and context is ready, append one plugin message
→ otherwise return the downstream result unchanged
```

完整 message batch 有助于 recall，因为其中包含宿主和 plugin context。Capture 更严格：只有 `source.kind === "user"` 的 text 才会成为 Source。全是 plugin message 的 batch 不会被误当成 user input。

能否注入由 `next()` 的结果决定。Recall 在 `next()` 前执行，但只有 downstream 返回 `kind: "enter"`，plugin 才会追加 context。Reject、无 context、校验失败或 wrapping 失败都会原样保留下游结果。Plugin 也不会为了补救注入失败而再次调用 `next()`。

## Scope

Scope 按以下顺序解析：

1. `POWERCONTEXT_DSH_SCOPE_ID` 或 plugin `scopeId`；
2. session workspace 的 normalized Git remote identity；
3. 根据 workspace path 生成的稳定 SHA-256 identity。

DSH 没有实现 Codex 与 Claude Code 使用的 Git-private Workstream binding 或 picker。Plugin 刻意不使用 process directory 作为 fallback。Session 没有 `cwd`，且未显式配置 Scope 时，自动路径会跳过，`/pc` 会报告 unscoped state，tool 会返回稳定的 `unscoped` result，并且不会发出 HTTP call。这样能避免无关的 DSH session 意外共享 Memory。

Model tool caller 不能覆盖 Scope。Plugin 会用 runtime-resolved value 覆盖 caller 提供的 `scope_id`。显式 Scope 应来自可信部署配置，而不是 model input。

## 注入、capture 与 flush

PreparedContext 在注入前必须通过 exact v1 schema、status、integer byte count、UTF-8 byte count 与 configured size 检查。默认上限是 8,000 bytes；配置范围是 512 到 32,768 bytes。注入消息会标记为宿主提供的、不可信历史证据，只服务于本次 model entry，不会再次作为 user content 被 capture。

Capture 写入确定性的 `dsh-user-prompt:` Source，并保留 DSH session 与 turn provenance。Recall 失败不影响 capture；capture 失败也不会丢掉有效 PreparedContext。超过 200,000 characters 的内容会跳过。设置 `POWERCONTEXT_DSH_CAPTURE_PROMPTS=false` 可以关闭 capture。

Capture 还会跳过包含 `sk-`、`api_key` 或 `BEGIN PRIVATE` 这些窄匹配 marker 的文本。这只是 guardrail，不是完整的 secret detection。如果 prompt 不应持久化，请关闭 capture。

Automatic flush 可选，默认关闭。启用 `flushOnCapture` 后，positive capture position 最多触发 `flushMaxCalls` 次尝试，并在 `current_cursor >= position` 时提前停止。`/pc flush` 是显式人工路径。如果 cursor 始终追不上，loop 会用完上限，却不能证明 Source 已被处理。不能从成功的 capture log 推断 Memory：处理可能产生 Candidate，Review 可以 commit Memory，也可以 no-op。

## 原生 tools 与 permission

Model surface 包含 19 个 curated named HTTP tools，不是 MCP。它们覆盖 Memory、prepare/capture、low-level Handoff、Experience 与 Skill generation/read，以及 read-only Candidate list/get。

Generic operation invocation、dangerous/admin operations 与 Candidate approve/reject/revise 在 model surface 上属于 **Unsupported**。High-level `create_work_contract`、`handoff_current_work`、`acknowledge_handoff` 与 `record_task_outcome` 也没有注册到该 surface，尽管相关 operation 存在于 generated HTTP 契约 中。

Read tools 会继续经过 `tools/pre-execute`。Memory write、显式 Source capture、Handoff activate/commit 与 Experience/Skill generation 这些 named mutation 会在执行前返回 `ask`。Permission UI 与 allow/deny decision 由 DSH 负责，因此这些 mutation 属于 **Host-gated**。Unit tests 已证明 `ask` classification；真实宿主中的 exact UI 与 denial path 为 **Not validated**。

Candidate review 保持人工控制。`/pc review approve` 与 `/pc review reject` 都要求 Candidate expected version。`/pc` 没有实现 Candidate revise。生成 Experience 或 Skill Candidate 是另一类 Host-gated mutation，不等同于 approval。

## 失败行为

Automatic prepare、validation、capture、optional flush 与 message wrapping 都 fail open。HTTP client 将 response 限制在 1 MiB，拒绝 redirect，取消 timeout request，并把 transport failure 规范成稳定的 unavailable result。整体 pre-step budget 默认四秒，单个 request 默认一秒。这些 failure 不能替换 downstream Agent result。

显式 durable operation 不同。Permission denial 与 Server error 必须保持可见，不能伪装成成功。Missing `cwd` 是 unscoped state，不是 empty Memory result。

## 负向实验

升级 DSH 或 plugin 时，建议跑这些检查：

- 停止 Server，再发送普通 prompt。Agent 应继续运行，只是没有 injected context；explicit write 应报告失败。
- 提交同时包含 user text 与 plugin text 的 batch。Recall 应看到两者，capture 只能包含 user-originated text。全是 plugin text 的 batch 不应创建 prompt Source。
- 让 downstream 返回非 `enter` decision。Plugin 不应追加消息。这个分支已经实现，但 dedicated real-host acceptance test 仍为 **Not validated**。
- 不配置 Scope，同时移除 session `cwd`。确认 HTTP request 不会使用 plugin process directory，command 与 tool 都报告 unscoped behavior。
- 返回 unknown PreparedContext field、错误 byte count、oversized body、redirect 或 slow response。不得发生 injection，下游 decision 应保持不变。
- 提交包含 `sk-`、`api_key` 或 `BEGIN PRIVATE` 的 capture text。它应被跳过。再测试另一种 credential shape，确认 filter 的覆盖范围刻意很窄。
- 让 flush cursor 始终落后于 Source position，直到用完 call bound。Turn 应继续，但不能谎报 processing 或 Memory。
- 分别调用 read 与 named mutation。Read 应 delegate；mutation 应在 write 前返回 `ask`。真实 permission UI 需要单独验证。
- 检查 model tools。Candidate approve/reject/revise、generic invocation 与 dangerous/admin operations 都不应出现。

## Unsupported 与 Not validated

| State | Capability | Practical consequence |
|---|---|---|
| **Unsupported** | 此 plugin 中的 MCP transport | 使用 native HTTP client 与 `pc_*` surfaces。 |
| **Unsupported** | automatic assistant final-response capture 与 automatic Task Outcome | 通过可用的受控 surface 显式持久化真实 completion boundary。 |
| **Unsupported** | Codex/Claude 风格 Git-private Workstream binding 与 picker | DSH 使用 configured Scope、Git remote 或 workspace-path identity。 |
| **Unsupported** | generic、destructive 或 admin model tools；model-driven Candidate decision | 使用 curated tools 与人工 `/pc review` approve/reject path。 |
| **Unsupported** | bounded automatic flush 之后的 cursor-through completion guarantee | 把它视为 bounded best-effort wait，不是 Memory generation 证明。 |
| **Not validated** | 正式最低 DSH version 或与某个 named release 的兼容性 | 不要把 development dependency 或本机 CLI version 当成支持下限。 |
| **Not validated** | 完整真实 `dsh web` host-process/model E2E | Package E2E 与 HTTP call-through 不能证明完整 host lifecycle。 |
| **Not validated** | 真实 host policy 下的 exact permission UI 与 denial behavior | Plugin 返回 `ask`；交互与最终 decision 由 DSH 负责。 |
| **Not validated** | dedicated real-host non-`enter` suppression 与 cursor-behind flush behavior | 对外声明 deployment 能力前，先运行负向实验。 |

`test_dsh_http_chain.py` 验证关闭 MCP 后的 native public Client/Server HTTP 契约。Cordis harness 覆盖 plugin 对 live Server 的 call-through。两者都没有启动真实 DSH host。


## 配置默认值

环境变量可以覆盖连接和 capture。`timeoutMs`、`requestTimeoutMs`、`maxBytes` 和 `flushMaxCalls` 是 plugin patch 设置，不是环境变量。

| Key | 默认值 | 含义 |
|---|---|---|
| `POWERCONTEXT_DSH_BASE_URL` | `http://127.0.0.1:8000` | 正在运行的 Server |
| `POWERCONTEXT_DSH_SCOPE_ID` | 未设置 | 显式 Scope；无 workspace cwd 时必须设置 |
| `POWERCONTEXT_DSH_AUTHORIZATION` | 未设置 | 完整 Authorization header |
| `POWERCONTEXT_DSH_CAPTURE_PROMPTS` | `true` | 采集 user-originated prompt |
| `POWERCONTEXT_DSH_FLUSH_ON_CAPTURE` | `false` | 测试用 flush |
| `maxBytes` | `8000` | Recall budget，限制在 `512–32768` |
| `timeoutMs` | `4000` | pre-step 总预算 |
| `requestTimeoutMs` | `1000` | 单次 HTTP timeout |

不要把 token 写进 patch 文件或 Server URL。当前工作不能落成 Source 时：

```bash
export POWERCONTEXT_DSH_CAPTURE_PROMPTS=false
dsh web
```


## 在这个宿主上做完统一题

> 修改 OpenAPI 契约后，下一步应该做什么？

1. 在固定 Scope 里用 `pc_remember` 保存答案。先过 `tools/pre-execute` 的 `ask`，再看 Citation。
2. 换一个会 `enter` 模型的新请求，再问同一句。
3. 召回必须带 Citation，并且只出现在 enter 之后、以 `PowerContext host-supplied context` 开头的 plugin message。
4. 停掉 Server 后再问。自动 recall 可以失败；非 enter 的 downstream 结果不得被替换。
5. 再跑 `pc_remember`。失败必须可见，不能伪装成 empty success。
