## 成熟度与安装

当前 integration 有 契约测试，以及 public/authenticated service-chain tests。它的自动路径刻意保持很窄：只运行 `UserPromptSubmit`。Setup 会安装 user-scope marketplace plugin，其中包含 Hook、HTTP MCP 配置与 bundled `project-context` Skill。

```bash
powercontext setup claude-code \
  --source oceanbase/powercontext \
  --ref master \
  --server-url http://127.0.0.1:8000

powercontext server run
powercontext doctor claude-code
```

Setup 会先打印 mutation plan，再开始改动。它会为现有 Claude Code settings 建 snapshot，保留安装前已经存在的 marketplace/plugin；安装或验证失败时，再恢复这份 snapshot。

## 最小用法

新开一个 Claude Code session。先在 `/hooks` 查看 `UserPromptSubmit`，再到 `/mcp` 确认 PowerContext Server 已连接。之后把两条路径分开使用：

1. 正常提一个 coding question。Hook 可以 recall context，但自动 capture 的只有你的 prompt Source。
2. 需要精确操作时，让 Agent 通过 MCP 搜索或维护 Memory。
3. 只有确实想在当前 turn prepare 并 commit durable Handoff 时，才说 `handoff this work`。

Bundled Skill 会提供这些使用规则。Hook 不会把每条 prompt 直接变成 Memory；MCP write 也不能替代用户的明确意图。

## 执行流程

```text
UserPromptSubmit
→ prompt (compatibility fallback: user_prompt)
→ resolve shared project Scope
→ prepare and capture independently
→ optional flush
→ additionalContext
```

v1 没有第二个 automatic event。尤其是 turn 结束时，plugin 不会读取 transcript。

## Scope

第一次调用 Memory operation 前，Skill 会运行 project Scope resolver。解析顺序如下：

1. 如果设置了 `POWERCONTEXT_CLAUDE_SCOPE_ID`，优先使用它；
2. 使用与 Codex 共享的 Git-private Workstream binding；
3. 使用 normalized Git remote identity，再回退到 normalized project path。

Workstream binding 存在 checkout 的 Git directory 下，不会提交到仓库。若多个 Workstream 都可能影响结果，Agent 必须让你选择，不能自行猜测。选定后，它会绑定返回的 `scope_id`，重新解析，并在写入 Handoff 前要求结果完全一致。

## Injection

Hook 会验证 prepared-context schema，再通过 `hookSpecificOutput.additionalContext` 返回临时上下文。这些内容只影响当前 turn；它不是 transcript capture，也不会因为 Claude 看过就自动持久化。

Recall 采用 fail-open。Server 不可用、response 无效、schema 未知、body 过大、发生 redirect 或 wall-clock budget 用尽时，都不注入，但也不阻塞宿主任务。Diagnostics 不包含 prompt、Scope、prepared content 或 authorization value。

## Capture 与 flush

Automatic capture 会把当前 user prompt 写入 `/v1/sources/content`，Source ID 使用稳定的 `claude-code-user-prompt:` 前缀。它不会 capture Claude final response，也不会记录 Task Outcome。

Recall 与 capture 彼此独立。Recall 失败不妨碍 capture；capture 失败也不会删掉有效的 `additionalContext`。设置 `POWERCONTEXT_CLAUDE_CAPTURE_PROMPTS=false` 可关闭 capture。设置 `POWERCONTEXT_CLAUDE_FLUSH_ON_CAPTURE=true` 可启用 optional flush；Hook 会重试 `/v1/memory/flush`，直到 `current_cursor >= position`，同时受 `POWERCONTEXT_CLAUDE_FLUSH_MAX_CALLS` 和共享 HTTP deadline 限制。

Capture 仍只是 Source evidence。最终是否生成或更新 Memory，由 Source window Trigger 与 candidate pipeline 决定。

## MCP、Skill 与 permission

`.mcp.json` 连接 HTTP MCP Server。`headersHelper` 从环境读取完整的 `POWERCONTEXT_CLAUDE_AUTHORIZATION` value，只在它存在时输出 `Authorization` header。Token 不会进入 plugin config、prompt 或 diagnostics。远程 endpoint 必须使用 HTTPS。

MCP 提供精确的 Memory maintenance、工作契约、Prepared/committed Handoff、acknowledgement、Outcome 与 Review operations。Skill 把直接的 `handoff this work` imperative 视为一次 durable Handoff 的授权：检查 live state，只调用一次 `handoff_current_work`，在同一 turn 将返回的 `handoff` 原样传给 `commit_handoff`，并且只在拿到 exact Revision 后报告成功。

问题、设计讨论或 preview request 都不构成 write 授权。做 preview 时，只在 chat 中展示拟议字段，不能产生 PowerContext write。不要用 `handoff_current_work` 实现 no-write preview：即使不调用 `commit_handoff`，它仍会记录 boundary Source。

Durable MCP mutation 需要 approval、但 Claude Code 没有 permission UI 时，宿主会如何处理，目前是 **Not validated**。不要在这里声称它具有 Pi 稳定的 `confirmation_required` 行为。

## Unsupported 与 Not validated

| 状态 | 能力 | 实际影响 |
|---|---|---|
| **Unsupported** | v1 `Stop` Hook | Session stop 时不会运行 automatic work。 |
| **Unsupported** | transcript 或 assistant final-response capture | 如需持久化 final result，必须显式调用 MCP operation。 |
| **Unsupported** | automatic Task Outcome | 在真实 completion 或 interruption boundary 调用 `record_task_outcome`。 |
| **Not validated** | 正式最低 Claude Code version | 2.1.133 是兼容性证据，不是版本下限。 |
| **Not validated** | 无 UI 时拒绝 durable mutation | 保留这项不确定性，不承诺宿主一定拒绝。 |

## 负向实验

在认定 integration 完成前，跑一遍这些实验：

- 停掉 Server，提交普通 prompt，确认 Claude Code 仍继续运行。
- 让 recall 失败而 capture 成功；再反过来，确认有效 `additionalContext` 仍保留。
- 返回未知 PreparedContext schema，确认不发生 injection。
- 让 Hook request redirect，确认 Authorization 不会被转发。
- 超过 response-size 或 deadline budget，确认 turn 能在有限时间内结束。
- 启用 flush，让 `current_cursor` 一直落后于 Source position，确认重试会停止，也不会声称 Memory 已存在。
- 让 Handoff preparation 成功、commit 失败；报告 boundary Source 已写入，但 durable milestone 不存在。
- 请求 preview，确认没有 PowerContext write。


## 配置默认值

非敏感选项可以写进 setup，也可以用环境变量覆盖这一次启动：

| Key | 默认值 | 含义 |
|---|---|---|
| `--server-url` / `POWERCONTEXT_CLAUDE_SERVER_URL` | `http://127.0.0.1:8000` | Hook 使用的 Server；也可来自 `pluginConfigs` 或 `CLAUDE_PLUGIN_OPTION_SERVER_URL` |
| `POWERCONTEXT_CLAUDE_SCOPE_ID` | 未设置 | 显式 Scope；未设置则与 Codex 同一套推导 |
| `POWERCONTEXT_CLAUDE_AUTHORIZATION` | 未设置 | 完整 Bearer header；Hook 和 MCP `headersHelper` 都读它 |
| `POWERCONTEXT_CLAUDE_CAPTURE_PROMPTS` | `true` | 也可被 `CLAUDE_PLUGIN_OPTION_CAPTURE_PROMPTS` 覆盖 |
| `POWERCONTEXT_CLAUDE_FLUSH_ON_CAPTURE` | `false` | 测试用 flush |
| `POWERCONTEXT_CLAUDE_REQUEST_TIMEOUT_SECONDS` | `1` | 单次 HTTP timeout |
| `POWERCONTEXT_CLAUDE_HTTP_BUDGET_SECONDS` | `4` | 一轮 prepare/capture 总预算 |
| `POWERCONTEXT_CLAUDE_FLUSH_MAX_CALLS` | `4` | flush 最多调用次数；允许 `1–16` |
| Recall budget | `8000` | Hook 发给 `prepare_context` 的 `max_bytes`；没有对应 env |
| Hook timeout | `10` | Claude Code 外层 hook timeout，单位秒 |

`POWERCONTEXT_CLAUDE_*` 优先于 `CLAUDE_PLUGIN_OPTION_*` 和 plugin options。不要把 token 写进 Server URL、plugin options、`.mcp.json` 或日志。`headersHelper` 只从环境读取完整 Authorization。远程 endpoint 使用 HTTPS。

Setup 写入的 `.mcp.json` 字段是：

```json
{
  "powercontext": {
    "type": "http",
    "url": "http://127.0.0.1:8000/mcp"
  }
}
```

真实文件还会带 `headersHelper`，从 `POWERCONTEXT_CLAUDE_AUTHORIZATION` 组装 header；URL 也可以来自 `user_config.server_url`。对照时只看这三项：`type`、`url` 指向 `/mcp`、文件里没有 token。

新 session 里对照：

1. `/hooks` 有 `UserPromptSubmit`。
2. `/mcp` 显示 `powercontext` Server connected。
3. 工具列表有 `remember_memory`，没有 `prepare_context`。

```bash
export POWERCONTEXT_CLAUDE_CAPTURE_PROMPTS=false
claude
```


## 在这个宿主上做完统一题

> 修改 OpenAPI 契约后，下一步应该做什么？

1. 在固定 Scope 里用 MCP `remember_memory` 保存答案。不要只靠 prompt Source。
2. 开一个新 session，用 `/hooks` 和 `/mcp` 确认激活，再问同一句。
3. 召回必须带 Citation，并且只出现在 `additionalContext`。v1 不会自动采集 assistant final response。
4. 停掉 Server 后再问普通编码问题。Claude Code 应继续。
5. 再做一次显式 MCP write。失败必须可见。
