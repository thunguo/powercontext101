<Warning>
Claude Code 2.1.133 是已知兼容背景，不是正式最低版本。真实 host-process E2E 是 **Not validated**。Permission 属于 **Host-gated**；无 UI 拒绝 durable write 目前 **Not validated**。managed Skill export 对 target `claude_code` 是 **Supported**。
</Warning>

Claude Code v1 只在 `UserPromptSubmit` 自动运行。它 prepare 一次有界上下文，独立 capture 当前 user prompt，再通过 `additionalContext` 返回临时内容。Setup 命令是 `powercontext setup claude-code`（连字符）。Skill export target 是 `claude_code`（下划线）。不要混。

完整安装看 [官方文档](https://oceanbase.github.io/powercontext/) 的 Configure Claude Code how-to。本页只写 101 的验证合同。

## 安装并激活

先确认两个 CLI 都在同一环境里：

```bash
powercontext --version
claude --version
```

再启动 Server，并在另一个终端安装 user-scope plugin：

```bash
powercontext server run
```

```bash
powercontext setup claude-code \
  --source oceanbase/powercontext \
  --ref master \
  --server-url http://127.0.0.1:8000

powercontext doctor
powercontext doctor claude-code
```

Setup 开始前会报告 settings 文件、plugin cache、data 目录和 rollback 命令。然后它：

1. 在 user scope 注册 marketplace `powercontext`；
2. 安装并启用 `powercontext@powercontext`；
3. 把 `server_url` 与 `capture_prompts` 原子合并进用户 `pluginConfigs`，并保留无关设置。

这些文件落在 `CLAUDE_CONFIG_DIR`，未设置时是 `~/.claude`：

```text
settings.json
plugins/cache/powercontext/powercontext/<version>
plugins/data/powercontext-powercontext
```

失败时 setup 恢复 settings snapshot，并只撤回本次新建的 marketplace / plugin。它不会启动 Server。

`doctor claude-code` 只检查 `claude` 是否在 PATH，以及 plugin list 里 PowerContext 是否 enabled。它不联系 Server，不测 recall。

装完后开一个**新** session：

```bash
claude
```

用 `/hooks` 确认 `UserPromptSubmit`，用 `/mcp` 确认 `powercontext` Server connected。

## 配置默认值

非敏感选项可以写进 setup，也可以用环境变量覆盖这一次启动：

| Key | 默认值 | 含义 |
|---|---|---|
| `--server-url` / `POWERCONTEXT_CLAUDE_SERVER_URL` | `http://127.0.0.1:8000` | Hook 使用的 Server；也可来自 `pluginConfigs` 或 `CLAUDE_PLUGIN_OPTION_SERVER_URL` |
| `POWERCONTEXT_CLAUDE_SCOPE_ID` | 未设置 | 显式 Scope；未设置则与 Codex 同一套推导 |
| `POWERCONTEXT_CLAUDE_AUTHORIZATION` | 未设置 | 完整 Bearer header；Hook 和 MCP `headersHelper` 都读它 |
| `POWERCONTEXT_CLAUDE_CAPTURE_PROMPTS` | `true` | 也可被 `CLAUDE_PLUGIN_OPTION_CAPTURE_PROMPTS` 覆盖 |
| `POWERCONTEXT_CLAUDE_FLUSH_ON_CAPTURE` | `false` | 测试用 flush |
| `POWERCONTEXT_CLAUDE_REQUEST_TIMEOUT_SECONDS` | `1` | 单次 HTTP timeout |
| `POWERCONTEXT_CLAUDE_HTTP_BUDGET_SECONDS` | `4` | 一轮 prepare/capture 总预算 |
| `POWERCONTEXT_CLAUDE_FLUSH_MAX_CALLS` | `4` | flush 最多调用次数；允许 `1–16` |
| Recall budget | `8000` | Hook 发给 `prepare_context` 的 `max_bytes`；没有对应 env |
| Hook timeout | `10` | Claude Code 外层 hook timeout，单位秒 |

`POWERCONTEXT_CLAUDE_*` 优先于 `CLAUDE_PLUGIN_OPTION_*` 和 plugin options。不要把 token 写进 Server URL、plugin options、`.mcp.json` 或日志。`headersHelper` 只从环境读取完整 Authorization。远程 endpoint 使用 HTTPS。

```bash
export POWERCONTEXT_CLAUDE_CAPTURE_PROMPTS=false
claude
```

## 最小验证

```bash
powercontext doctor
powercontext ready
powercontext capabilities
```

在 Claude Code 里显式保存：

```text
Use PowerContext to remember this decision:
after changing the OpenAPI contract, regenerate the client and inspect the diff.
Return the Memory Citation. Do not store secrets.
```

MCP `remember_memory` 不需要 generation model。成功时应返回 exact Citation。

换一个新 session，问：

```text
What should happen after the OpenAPI contract changes?
```

自动召回成功时，`additionalContext` 带 Citation，并标成 untrusted historical evidence。Prompt Source 可以存在；assistant final response 不会被 v1 plugin 自动采集。

## Scope 解析

Claude Code 与 Codex 共用同一套顺序：

1. 非空的 `POWERCONTEXT_CLAUDE_SCOPE_ID`。
2. Git-private Workstream binding：`.git/powercontext/codex-workspace.json`。
3. 规范化后的 Git `remote.origin.url`。
4. 项目目录的 `local:<sha256>`。

有 binding 时，两边得到完全相同的 Workstream Scope。没有 binding 时，仍共享规范化 remote。只满足“目录看起来一样”还不够；先核对最终 `scope_id`。

## 自动路径与显式工具

```text
UserPromptSubmit
→ prompt (compatibility fallback: user_prompt)
→ resolve shared project Scope
→ recall and capture independently
→ optional flush
→ additionalContext
```

当前 v1 plugin 明确没有：

- Stop Hook；
- transcript 读取；
- assistant final response 自动 capture；
- 自动 Task Outcome。

不要因为 Claude Code 提供其他事件，就把它们写进当前 plugin contract。

Recall failure 不阻止 capture；capture failure 不删除 valid `additionalContext`。Hook 拒绝 redirect，限制 response size 与 wall-clock deadline，诊断不含 prompt、Scope、content 或 token。

MCP 负责 exact Memory maintenance、Prepared/committed Handoff、acknowledgement、Outcome 和 Review。最终结果要持久化时必须显式调用。`project-context` Skill 指导 one-turn Handoff，但 commit 仍需明确祈使句。插件 README 若写 Review 未暴露，以当前 Server MCP 投影为准。

`powercontext skill export --target claude_code` 才是 managed Skill export。Bundled Skill 不是它。

## 负向检查

- 停掉 Server 后再做普通编码任务。Claude Code 应继续。
- Server 仍停着时再显式 MCP write。失败必须可见。
- Empty / 401 / 404 / 503 / unknown schema：不注入，并留下对应 content-free outcome。
- 无 UI 拒绝 durable write：当前 **Not validated**，不要照搬 Pi。
- 用旧 Citation mutation：返回 conflict。

## 当前限制

- 真实 Claude Code host-process E2E 是 **Not validated**。
- 2.1.133 只是已知兼容背景，不是 version gate。
- v1 不读 transcript，也不在 Stop 时收尾。
- 自动 extraction 需要 generation model；显式 Memory 不需要。
- `setup claude-code` 与 export target `claude_code` 是两个不同名字。

## 在这个宿主上做完统一题

> 修改 OpenAPI 契约后，下一步应该做什么？

1. 在固定 Scope 里用 MCP `remember_memory` 保存答案。不要只靠 prompt Source。
2. 开一个新 session，用 `/hooks` 和 `/mcp` 确认激活，再问同一句。
3. 召回必须带 Citation，并且只出现在 `additionalContext`。v1 不会自动采集 assistant final response。
4. 停掉 Server 后再问普通编码问题。Claude Code 应继续。
5. 再做一次显式 MCP write。失败必须可见。

## 完成检查

- `doctor claude-code` 看到 plugin enabled。
- `/hooks` 有 `UserPromptSubmit`，`/mcp` 显示 Server connected。
- 新 session 能召回你显式保存的 OpenAPI decision，Citation 出现在 `additionalContext`。
- Prompt Source 存在，assistant final response 不存在。
- 自动 recall 失败时，普通编码任务仍继续。
- 显式 Memory 或 Handoff 失败时，Claude Code 把错误告诉你。
- 与 Codex 共享时，两边最终 `scope_id` 逐字相同。
- 你没有把 `claude-code` 和 `claude_code` 混用，也没有把 bundled Skill 当成 export。
