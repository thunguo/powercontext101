<Warning>
当前没有统一的 `HostAdapter` SDK。本页的 契约 名称是设计 checklist，不是已有 class 或稳定 public API。
</Warning>

## 从 capability discovery 开始

不要先复制最相近的 integration。先记录新宿主实际能提供什么：

- 稳定的 prompt event 及其 ordering；
- turn、message、session、workspace 和 project identity；
- model dispatch 前的 transient injection channel；
- tool 与 command registration；
- permission request、confirmation UI 和 headless behavior；
- package、plugin 与 bundled Skill installation；
- end、compaction、switch、shutdown 与 interruption events；
- CLI/version probe 和 activation probe。

同时查询 `GET /v1/capabilities`。它会返回 `memory_extraction`、`experience_generation`、`managed_skill_generation`、`external_skill_registry`、Handoff generation、search modes 和 context versions 等 Server capability。Host capability discovery 与 Server capability discovery 回答的问题不同，两者都需要。

如果宿主没有稳定 prompt event、pre-dispatch injection point 或 permission surface，就直接写明。除非你实现了保证等价的另一套 契约，否则该 capability 是 **Unsupported**。如果宿主看起来提供了入口，但没有 real-host test 证明完整路径，则标为 **Not validated**。

## 编写 适配器契约

用以下 vocabulary 把关键决策摆到台面上：

```text
PromptEvent
ScopeResolver
PreparedContextProvider
TransientInjector
SourceCapture
FlushCoordinator
ToolSurface
PermissionGate
Diagnostics
Installer / Doctor
```

这些是建议的角色。每项都要定义 input、output、failure policy、security boundary 和 observable assertion。

| Role | 需要明确的 契约 |
|---|---|
| `PromptEvent` | 精确 host event、prompt normalization、lifecycle ordering 和稳定 turn identity。 |
| `ScopeResolver` | Authorized override、Git identity、project fallback、normalization 与 cache lifetime。 |
| `PreparedContextProvider` | `/v1/context/prepare`、接受的 schema versions、response-size budget 与 fail-open result。 |
| `TransientInjector` | Context 从哪里进入、如何标记为 untrusted，以及 injection 不会持久化的证据。 |
| `SourceCapture` | Capture 内容、deterministic Source identity、metadata、secret policy、UTF-8 byte limit 与返回的 `position`。 |
| `FlushCoordinator` | 每个 Scope 的 pending state、boundary events、retry/deadline budget 与 `current_cursor >= position` 清除规则。 |
| `ToolSurface` | 精确 operation allowlist、generated schema source、tool result shape 和 unsupported operations。 |
| `PermissionGate` | Read 与 mutation、approval UX、denial、cancellation，以及无 UI 时的行为。 |
| `Diagnostics` | Activation、version、package ownership、Server state 与不含内容的错误报告。 |
| `Installer / Doctor` | Idempotency、ownership、rollback、activation probe 与 partial-failure status。 |

Automatic recall、capture 和 optional flush 可以 fail-open。Explicit durable write、Review、Handoff commit 与 Skill export 必须报告失败。不能给两组操作套用同一 policy。

## 最小用法

先只实现一条 prompt path、一条 boundary path 和一个 explicit mutation。第一版不要带入任何 unsupported capability。

## 执行流程

Host glue 要薄。它只负责解析 identity、调用已验证 helper，并把结果转换成宿主的 native event shape。

```text
onPrompt(event)
→ normalize PromptEvent
→ resolve Scope
→ prepare context and capture Source independently
→ retain returned position for bounded flush
→ inject PreparedContext through the host's transient channel

onBoundary(event)
→ flush pending position for the same Scope

onMutation(call)
→ validate Scope and payload
→ request host permission
→ execute only after approval
```

如果宿主无法实现其中某个箭头，就删掉对应 claim。不要用一个泛化的 adapter 名称掩盖缺口。

## 复用现有实现

只复用 契约 与宿主一致的代码：

- `powercontext.http` 下的 generated HTTP client 与 transport models；
- canonical `PreparedContext` 和 capability models；
- Python capture rendering 与 redaction helpers；
- shared loopback transport vectors；
- Codex 与 Claude Code 的 prepared-context validation patterns；
- host-specific Scope normalization tests；
- Pi 的 pending-position flusher pattern；
- DSH 等 integration 的 generated operation tables；
- Codex 与 Claude Code managed Skill projections；
- first-class setup/doctor catalog 与通用 `Diagnostic` value model。

目前仍有不少 helper 是重复实现，而不是共享实现。Scope resolution、PreparedContext validation、deadline/redirect policy、secret detection、Source ID construction 和 bounded flush logic 仍分散在各 host package 中。文件名相似，不代表它们组成了 supported SDK。

## Scope、injection、capture 与 flush

新宿主必须一起定义这四个边界。

Scope 应来自稳定、授权后的 project data。Git remote 要去除 credential。不要信任模型提供的 `scope_id`；除非 宿主契约 证明 session identity 与 repository identity 相同，也不要混用两者。

Injection 应在 model dispatch 前使用宿主的 native transient channel，并把 `PreparedContext` 标为不可信的历史证据。只在 system guide 里告诉模型搜索 Memory，不能证明 recall 已注入。

Capture 要明确记录 turn 的哪一侧。Transport 前过滤 secret-shaped content，并按 UTF-8 bytes 执行 limit。Recall 与 capture 要彼此独立，避免一个失败清掉另一个的有效结果。

Flush 要按 Scope 保存 Source `position`，且仅在 `current_cursor >= position` 时清除。每个 retry loop 都要有 call limit 和 wall-clock budget。宿主没有可靠 boundary event 时，automatic flush 为 **Unsupported**；event 存在但未在真实宿主中运行时，为 **Not validated**。

## Permission 与 explicit writes

列出所有 mutating operation。明确宿主在 interactive 和 headless 模式下能否 ask、deny、cancel 或 pause，再测试实际行为。

没有 permission API 的宿主不能继承 Pi 的 `confirmation_required` 契约，也不能继承 OpenCode 的 `context.ask()` behavior。可选方案只有三种：在 adapter-controlled code 中 fail closed、只提供 read-only operation，或把 durable mutation 标为 **Unsupported**。“模型应该先问”不是 permission boundary。

Diagnostics 不得输出 prompt content、prepared context、可识别 private repository 的 Scope details、authorization values 或含 secret 的 payload。

## Setup 与 doctor

Installation 与 activation 分开检查后，才能把宿主加入 setup。

Setup 应保持 idempotent，不覆盖 foreign same-name files，对自己管理的文件记录 ownership；remote refresh 使用 staging，并在失败时恢复之前的状态。Multi-host setup 要隔离各宿主失败，并把每个选中项报告为 installed、failed 或 skipped。

Doctor 有三项工作：

1. 找到 host executable，并报告 version evidence；
2. 确认 installed package 或 configuration 属于 PowerContext；
3. 如果宿主提供安全且不调用模型的 probe，通过宿主验证 activation。

不要把 `powercontext doctor` 当作 integration scan。通用命令检查 package 与 Server；host check 属于 `powercontext doctor <host>` 和只读的 `powercontext doctor integrations` matrix。

## Acceptance tiers

用以下 tier 描述证据。它们是本页的分类，不是当前 test framework 中的名称。

1. **契约/unit：** schema、Scope、size、secret、permission 与 failure-policy tests。
2. **Package/load：** build、install、import、manifest、command 或 plugin registration。
3. **Service chain：** real PowerContext Server，加上直接 hook/module execution 与 Source/Memory lineage。
4. **Real-host E2E：** 启动实际宿主，发送 prompt，观察 lifecycle、injection、capture、flush 与 permission behavior。
5. **Live provider journey：** 用实际 host 和 provider/model 运行，并保留 acceptance evidence。

Package/load 和 service-chain tests 很有用，但不能证明 host API compatibility 或 event ordering。标为 Supported 的每项 capability，都需要 real-host E2E。Provider behavior 影响 claim 时，还需要第五层证据。

## Negative matrix

至少测试以下情况：

| Area | Experiment | Required observation |
|---|---|---|
| Availability | Server down 或 request timeout | Automatic path 有界且 fail-open。 |
| Authentication | Wrong token | 不泄露 credential、prompt、context 或 private Scope。 |
| Transport | Redirect 或 plaintext non-loopback endpoint | 不跟随 redirect；拒绝不安全 transport。 |
| Schema | Unknown 或 incomplete PreparedContext | 不注入任何内容。 |
| Size | Oversized response 或 prompt | 在 configured byte budget 处停止。 |
| Identity | Missing、stale 或 caller-supplied Scope/turn ID | 不发生 cross-project 或 stale-turn injection。 |
| Capture | Disabled、secret-shaped 或 failed request | Recall 保持独立；不发送 forbidden Source。 |
| Flush | Cursor lag、transient failure 或 timeout | Pending position 保留；重试在 budget 内结束。 |
| Permission | Deny、cancel 或 no UI | 除非 declared 宿主契约 允许，否则 mutation 不运行。 |
| Capability | `memory_extraction=false` | Capture 仍只是 Source evidence；不声称 unsupported flush/extraction。 |
| Lifecycle | Compact、switch、shutdown、interruption | 只使用匹配的 Scope 与 turn state。 |
| Setup | Foreign file、failed refresh 或 failed activation | Existing state 保留，并报告 partial failure。 |

宿主有 private/group session 等概念时，再加入对应的 host-specific privacy case。

## Managed Skill export

Managed Skill export 当前只支持 Codex 和 Claude Code。其他 plugin 安装 bundled `project-context` Skill，不会改变这个 matrix。

新增 export target 时，需要实现 projection 契约、target enum 与 OpenAPI surface、ownership rules、validation、rollback 和 drift tests。在这些工作完成前，该宿主的 managed export 为 **Unsupported**。如果 implementation 已存在，但未运行 real install/refresh test，则标为 **Not validated**。

## Unsupported 与 Not validated

| 状态 | 使用条件 | Example |
|---|---|---|
| **Unsupported** | Code 明确拒绝、排除，或无法安全实现 capability。 | 没有 host permission API，也没有 adapter-controlled fail-closed mutation path。 |
| **Not validated** | 路径可能工作，但现有证据没有到达 claimed host/provider boundary。 | Hook 通过 unit 和 service-chain tests，但没有 test 启动真实宿主。 |

不要把这两个 label 合并成“limited support”。一个是 product boundary，另一个是 evidence gap。

## 完成 checklist

- [ ] Host 与 Server capability discovery 分开记录。
- [ ] 每个 proposed 契约 role 都有 input、output、failure policy 与 observable assertion。
- [ ] Host version gate 或 compatibility evidence，以及 activation probe 已存在。
- [ ] Scope 来自稳定、授权后的 identity，并去除 credential。
- [ ] PreparedContext 已校验、临时注入，并标为 untrusted。
- [ ] Capture 明确 content、Source identity、UTF-8 size limit 与 secret policy。
- [ ] Flush 按 Scope 保存 position，只在 `current_cursor >= position` 时清除。
- [ ] Explicit writes 已测试 allow、deny、cancel 与 no-UI behavior。
- [ ] Diagnostics 不输出 content 或 credential。
- [ ] Setup 保留 foreign config，并报告 rollback 或 partial failure。
- [ ] 除非完整 projection target 已存在，否则 managed Skill export 为 **Unsupported**。
- [ ] Real-host E2E 覆盖每项 Supported lifecycle 与 permission claim。
- [ ] **Unsupported** 与 **Not validated** 在 docs、tests 和 release notes 中保持区分。

完成这些，才把宿主加入 first-class catalog。
