Dashboard 是 Server 自带的只读统计页。它不会另存一份数据，也不会自动找出所有 <Tooltip headline="Scope" tip="决定这次请求读写哪一组数据。设错时通常不报错，只是搜不到。" cta="阅读 Scope" href="/zh/mental-model/scope">Scope</Tooltip>。更重要的是，它现在不展示 Memory 正文或 Citation。

你可以用它确认这个 Scope 有没有数据，Memory 条目怎么分布，以及 Source、Candidate 和召回数字有没有变化。

<img src="/assets/basic-dashboard-scope-zh.svg" alt="Dashboard 只核对数字：同一 Scope，同一数据库。" />

上一页 [常用 API 串讲](/zh/basic-usage/api-tour) 结束前会把示例 Memory 停用。所以 Dashboard 不应该显示“刚写下的 Memory 正文”。正确结果是同一个 Scope 下 `total=1`、`active=0`、`inactive=1`。

## 配上同一个 Scope

API 串讲会打印一个带 UUID 的 `scope:`。复制完整值，不要只取前缀。写进 `.env`：

```bash
POWERCONTEXT_SERVER_DASHBOARD_ENABLED=true
POWERCONTEXT_SERVER_DASHBOARD_SCOPES=[{"scope_id":"PASTE_THE_FULL_SCOPE","display_name":"PowerContext 101 API tour"}]
```

CLI 不会自己读 `.env`，所以要显式启动：

```bash
powercontext server run --env-file .env
```

打开：

```text
http://127.0.0.1:8000/
```

选刚配的 Scope。统计里应看到一条 Memory，并且它已经停用。Dashboard 只显示数字。要核对正文，回到 Python Client，用 `list_memory_entries(include_inactive=True)` 或精确 Citation 读取。

页面能打开但 Scope 列表是空的，先检查当前 Server 进程有没有加载 `POWERCONTEXT_SERVER_DASHBOARD_SCOPES`。列表有 Scope、数字却全是零，再检查客户端和 Dashboard 是不是同一个数据库 URL / `POWERCONTEXT_HOME`。换数据目录和换 Scope，看起来都很像“数据没了”。

<Warning>
Dashboard 发布用于把已批准托管 Skill 发到预先配置的目标。和本页的数字核对无关，也不是 `powercontext skill export`。
</Warning>

开了 Bearer 之后，`/` 仍能打开，但 Dashboard 要统计时需要同一个 Server 令牌。页面会提示你输入；不要把它拼进 URL。

## 怎么知道跑通了

成功不是“看见 Memory 文本”，而是 Dashboard 和客户端对同一个 Scope、同一套库给出一致数字。正文和历史仍由客户端、HTTP 或 MCP 精确读取。

Scope 和数据库已经一致，数字还对不上，先停在这里。用目标 `--env-file` 重启 Server，对这个进程再跑一遍 API 串讲，再逐字比较脚本打印的 Scope。Dashboard 为空或数字不一致是配置问题，不能据此判断 Memory 被删了。

对不上时，先看[排错](/zh/start/troubleshooting)。
