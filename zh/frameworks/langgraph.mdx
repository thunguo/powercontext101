## 最小用法

`create_react_agent` 已经会读取 recall hook 写入的 `llm_input_messages` channel。

```python
from langchain_core.messages import HumanMessage
from langgraph.prebuilt import create_react_agent
from powercontext_langgraph import PowerContextRecall, PowerContextScope, powercontext_tools

agent = create_react_agent(
    model,
    tools=powercontext_tools(),
    pre_model_hook=PowerContextRecall(),
    context_schema=PowerContextScope,
    checkpointer=my_checkpointer,
)

result = await agent.ainvoke(
    {
        "messages": [
            HumanMessage(content="What should happen after changing the OpenAPI contract?")
        ]
    },
    context=PowerContextScope(scope_id="project:powercontext-101"),
)
```

<Warning>
使用 `ainvoke` 或 `astream`。Recall 和三个 tools 都是 async；`invoke` 与 `stream` 无法执行它们。
</Warning>

| Tool | 行为 |
|---|---|
| `powercontext_search` | 搜索 Memory；默认 `limit=5`，最大 `20`；没有 search `mode` 参数 |
| `powercontext_remember` | 显式写入一条 Memory |
| `powercontext_context` | 为 query 准备有界 context |

`powercontext_search` 与 `powercontext_context` 会把模型给出的 query 截到 8,192 个 Python characters。`powercontext_tools()` 按 search、remember、context 的顺序返回 tools。

## 执行流程

```text
latest human message
→ resolve per-run Scope and connection settings
→ prepare_context(query <= 8192 chars, max_bytes)
→ build ordered llm_input_messages
→ model step
→ optional model-requested search / remember / context tool
→ later model steps reuse the per-turn recall cache
```

每个 model step 前都会调用 `PowerContextRecall`，但同一 human turn 最多 prepare 一次。ReAct loop 使用 Scope 加最新 human message ID 作为 cache key；没有 ID 时使用 message text。Key 包含 Scope，因此两个 tenant 的相同 prompt 不会共享 recall content。

Recall 成功时，输入最前面是一条标记为 untrusted historical evidence 的 `SystemMessage`，后面保持原始 messages 顺序。Recall empty 或失败时，只传原始 messages。

### 保持 model input 临时

Recall 把完整输入写到 `llm_input_messages`，从不把 recalled block append 到 `messages`，所以 checkpointer 不会积累 stale context。

Custom graph 必须声明这个 channel，在 model 前执行 recall，并由 model node 读取它：

```python
from typing import Annotated

from langchain_core.messages import BaseMessage
from langgraph.graph import START, StateGraph
from langgraph.graph.message import add_messages
from powercontext_langgraph import PowerContextRecall, PowerContextScope
from typing_extensions import TypedDict


class AgentState(TypedDict):
    messages: Annotated[list[BaseMessage], add_messages]
    llm_input_messages: list[BaseMessage]


async def call_model(state: AgentState):
    model_input = state.get("llm_input_messages") or state["messages"]
    response = await model.ainvoke(model_input)
    return {"messages": [response]}


builder = StateGraph(AgentState, context_schema=PowerContextScope)
builder.add_node("recall", PowerContextRecall())
builder.add_node("model", call_model)
builder.add_edge(START, "recall")
builder.add_edge("recall", "model")
graph = builder.compile(checkpointer=my_checkpointer)
```

如果只读 `state["messages"]`，模型会静默丢掉 recalled context。把 recalled block 写回 `messages` 则破坏 checkpoint boundary。

## Scope 与配置

多租户服务应在每次 invocation 传入 `PowerContextScope`。每个 run 的 Scope、base URL、token 和 timeout 会覆盖对应环境变量。

```python
scope = PowerContextScope(
    scope_id="tenant:acme:project:api",
    base_url="https://context.example.com",
    token="opaque-server-token",
    timeout=8.0,
)

result = await agent.ainvoke(state, context=scope)
```

| Setting | 默认值 |
|---|---:|
| `POWERCONTEXT_LANGGRAPH_BASE_URL` | `http://127.0.0.1:8000` |
| `POWERCONTEXT_LANGGRAPH_TOKEN` | 未设置 |
| `POWERCONTEXT_LANGGRAPH_SCOPE_ID` | 派生或报错 |
| `POWERCONTEXT_LANGGRAPH_TIMEOUT` | `10` seconds |
| `POWERCONTEXT_LANGGRAPH_MAX_BYTES` | `8000`；允许范围 `512`–`32768` bytes |

Scope precedence：

```text
PowerContextScope(scope_id=...)
→ POWERCONTEXT_LANGGRAPH_SCOPE_ID
→ normalized network Git origin
→ MissingScopeError
```

没有 local-path fallback。HTTP(S)、SSH、Git 和 SCP-like network remote 会在移除 credentials 后做 normalization；local path 或 Windows drive path 不是 remote。过长的显式 Scope 会被替换为有界的 SHA-256 identifier。

Token 采用不含 `Bearer ` 的 bare token 约定。Adapter 不严格校验该语法，部署前应拒绝错误配置。`repr=False` 只能减少意外显示，不是 secret vault。除非 caller 提供并显式标记 trusted transport，共享的 `PowerContextClient` 会拒绝向非 loopback host 使用明文 HTTP。

## 为什么没有 BaseStore

<Note>
LangGraph `BaseStore` 要求 `GetOp`、caller-keyed `PutOp` upsert/delete 和 `SearchOp`。只有 search 能自然映射到 PowerContext Memory。Memory identity 与 version 由 Server 分配，并不提供 caller-key get、put 或 delete 语义。
</Note>

Search-only store 可能通过 graph assembly，却在其他 node 发出 get 或 put 时失败。因此 adapter 使用 nodes 和 tools，不占用 `compile(store=...)`。

## Failure、隐私与 Scope boundary

Automatic recall 为 fail-open。Scope 缺失、配置错误、validation error、authentication failure、timeout 或 Server error 都会跳过 recalled block，让 graph 继续使用原始 messages。HTTP 401/403 会记录为配置问题，不会冒充 empty Memory。

Explicit tools 不会把失败伪装成 empty success，也不会把 exception 抛穿 graph。它们返回简短、model-visible 的 unavailable 或 invalid-request string，模型可以重试或继续。真正的 search miss 使用单独的 `(no matching PowerContext memory)` 结果。

<Warning>
Recalled content 可能包含旧 user 或 model text。它是 evidence，不是当前 instruction、identity proof 或 tool authorization。把它留在 `llm_input_messages`。Scope 只选择数据分区；需要隔离时，应从 authenticated tenant/project mapping 派生 Scope。
</Warning>

Adapter 不做 automatic capture。显式 `powercontext_remember` 仍会持久化模型选择的文本，因此要设置 host tool permission 和 retention policy。

## 完成检查清单

- Server 单独运行，source-installed adapter 固定到经过审阅的 commit。
- Graph 使用 `ainvoke` 或 `astream`。
- `PowerContextRecall` 在 model 前运行；custom model node 读取 `state.get("llm_input_messages") or state["messages"]`。
- 检查 checkpointer，确认 recalled block 从不进入 persisted `messages`。
- 每次 invocation 收到预期 Scope；cross-Scope test 证明相同 prompt 仍保持隔离。
- `MAX_BYTES` 在 512 到 32,768 之间，长 query 会在 8,192 characters 截断，remote transport 使用 HTTPS。
- Server unavailable 时 recall 让 graph 继续；explicit tool failure 对模型可见，并与 empty search 区分。
- Explicit Memory write 已纳入 tool permission 与 retention policy。
- 部署记录没有混淆 Unsupported 与 Not validated。
