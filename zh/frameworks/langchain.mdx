`PowerContextMiddleware` 接入 LangChain `create_agent`。它支持 sync 与 async，只修改当前 model request，并可把完成的 turn 捕获为 Source evidence。它没有 adapter-owned PowerContext tools。

<Note>
Middleware 与 `powercontext-langgraph` 相互独立。LangChain 内部可能安装 LangGraph，但两个 PowerContext adapters 使用不同的 settings、Scope types 和 lifecycle behavior。
</Note>

## 最小用法

```python
from langchain.agents import create_agent
from powercontext_langchain import PowerContextMiddleware, PowerContextScope

agent = create_agent(
    model,
    tools=application_tools,
    middleware=[PowerContextMiddleware()],
    context_schema=PowerContextScope,
)

result = await agent.ainvoke(
    {
        "messages": [
            {
                "role": "user",
                "content": "What should happen after changing the OpenAPI contract?",
            }
        ]
    },
    context=PowerContextScope(scope_id="project:powercontext-101"),
)
```

同一 middleware 在同步应用中支持 `invoke` 与 `stream`，在 async 应用中支持 `ainvoke` 与 `astream`。

<Warning>
不要在已经运行的 event loop 中调用同步 agent method。Host 仍会运行，但 PowerContext recall 与 capture 会被跳过，middleware 记录一次 warning。此时应使用 async agent API。
</Warning>

## 执行流程

```text
before every model request
→ read latest human message
→ resolve per-invocation Scope and connection settings
→ prepare_context(query <= 8192 chars, max_bytes)
→ append an untrusted block to this ModelRequest.system_message
→ call model without changing agent state
→ after successful agent completion, optionally capture latest user + final response
```

每个 model request 前都会 recall。它不像 Pydantic AI Capability 那样每个 run 一次，也不像 LangGraph 那样按 human turn prepare 一次并跨 model steps 使用 cache。因此，同一 run 中 application-owned tool 先写入 Memory，后续 model step 可能看到新内容。

Middleware 只 override 当前 `ModelRequest.system_message`，从不把 recalled block 写入 framework state 或 checkpointer。原有 system message 保持在前，untrusted context block 只 append 到这一次 request。

## Capture 默认关闭

只有在确认可以持久保存 user 与 final model content 后才开启 capture：

```python
middleware = PowerContextMiddleware(auto_capture=True)
```

`auto_capture` 默认为 `False`。`after_agent` 或 `aafter_agent` 只在成功完成后捕获，内容是最新的非空 user message，加上可序列化的 `structured_response` 或最后一条非空 assistant response。

| 包含 | 排除 |
|---|---|
| Latest user text | Tool output |
| Final assistant text | Intermediate tool-calling messages |
| 可序列化的 `structured_response` | Recalled PowerContext block |
| Truncation metadata | Aborted run 或没有 final response 的 run |

合并后的 Source payload 另有 200,000 Python-character 上限。Adapter 会在 user 与 assistant text 之间分配预算，并记录 truncation flags。

<Note>
Capture 创建 Source，不创建或批准 Memory，middleware 也不 flush。Server extraction 可以稍后由 scheduler 或显式 Client operation 触发，也可能得到 no-op。
</Note>

## Scope 与配置

一个 agent 服务多个 tenant 时，应在每次 invocation 传入 `PowerContextScope`。每次 invocation 的 Scope、base URL、token 和 timeout 会覆盖环境变量。

```python
scope = PowerContextScope(
    scope_id="tenant:acme:project:api",
    base_url="https://context.example.com",
    token="opaque-server-token",
    timeout=8.0,
)

result = await agent.ainvoke(state, context=scope)
```

| Setting | 默认值 |
|---|---:|
| `POWERCONTEXT_LANGCHAIN_BASE_URL` | `http://127.0.0.1:8000` |
| `POWERCONTEXT_LANGCHAIN_TOKEN` | 未设置 |
| `POWERCONTEXT_LANGCHAIN_SCOPE_ID` | 派生或报错 |
| `POWERCONTEXT_LANGCHAIN_TIMEOUT` | `10` seconds |
| `POWERCONTEXT_LANGCHAIN_MAX_BYTES` | `8000`；允许范围 `512`–`32768` bytes |

Scope precedence：

```text
PowerContextScope(scope_id=...)
→ POWERCONTEXT_LANGCHAIN_SCOPE_ID
→ normalized network Git origin
→ MissingScopeError
```

没有 local-path fallback。HTTP(S)、SSH、Git 和 SCP-like network remote 会在移除 credentials 后做 normalization。过长的显式 Scope 会被替换为有界的 SHA-256 identifier。

Token 采用不含 `Bearer ` 的 bare token 约定。Adapter 不严格校验该语法。除非 caller 提供并显式标记 trusted transport，共享的 `PowerContextClient` 会拒绝向非 loopback host 使用明文 HTTP。

## Failure、隐私与 Scope boundary

Automatic recall 与 capture 是相互独立的 fail-open paths。Scope 缺失、配置错误、request validation、authentication failure、timeout、Server failure，或无法序列化的 structured response，都不会替换 model result，也不会中止 host run。HTTP 401/403 会记录为配置问题，不会冒充 empty Memory。

Middleware 不添加显式 PowerContext tools。如果应用自行把 Python Client mutation 包装成 tool，其 失败契约 和 permission 归应用负责；automatic fail-open 不会让这些 mutation 假装成功。

<Warning>
Recall 可能包含旧 user 或 model text。它是 untrusted evidence，不是 instruction、identity proof 或 permission grant。Scope 只选择数据分区；需要隔离时，应从 authenticated tenant/project mapping 派生 Scope。
</Warning>

Capture 可能存储普通 prompt、代码、业务数据和 final model output。此 adapter 不承诺完整 secret redaction。在应用明确 content filtering、consent、retention 与 deletion rules 前，保持 `auto_capture=False`。排除 tool output 并不能替代隐私策略。

## 与 LangGraph 对比

| 能力 | LangChain | LangGraph |
|---|---|---|
| Recall frequency | 每个 model request | 每个 human turn 一次，跨 model steps 使用 cache |
| Adapter-owned tools | 无 | 三个 Memory tools |
| Automatic capture | 可选 completed-turn Source；默认关闭 | 无 |
| Invocation | Sync 与 async | 仅 async |
| Injection channel | 当前 `ModelRequest.system_message` | 临时 `llm_input_messages` |
| Framework state mutation | 无 | Recall 不修改 persisted `messages` |
| Flush | 无 | 无 |

## 完成检查清单

- Server 单独运行，source-installed middleware 固定到经过审阅的 commit。
- Sync code 在 event loop 外运行；async code 使用 `ainvoke` 或 `astream`。
- 捕获到的 model request 含 untrusted recall block，returned 与 checkpointed state 不含该 block。
- 测试按每个 model request 发生 recall 编写，而不是按 run 一次或 turn 一次。
- 每次 invocation 收到预期 Scope；cross-Scope negative test 证明 tenant isolation。
- `MAX_BYTES` 在 512 到 32,768 之间，超过 8,192 characters 的 query 会被截断，remote transport 使用 HTTPS。
- Server unavailable 时 model flow 继续，401/403 仍能与 empty Memory 区分。
- 除非 completed-turn storage 已有明确的 privacy 与 retention policy，否则 `auto_capture` 保持关闭。
- Capture 开启时检查 Source，不假定 Memory 已生成或 flush 已发生。
- 部署记录没有混淆 Unsupported 与 Not validated。
