`PowerContextMiddleware` 接入 LangChain `create_agent`。它在每次 model request 前 prepare，只修改当前 request，不写 agent state 或 checkpointer。它也不提供 PowerContext Memory tools。

## 安装

```bash
uv tool install --force \
  "powercontext[cli,server] @ git+https://github.com/oceanbase/powercontext.git@master"

uv pip install \
  "powercontext-langchain @ git+https://github.com/oceanbase/powercontext.git@master#subdirectory=integrations/langchain"

powercontext server run
```

当前 package 要求 LangChain 1.3+。可复现部署应 pin 经过验证的 commit。

## 最小接入

```python
from langchain.agents import create_agent
from powercontext_langchain import (
    PowerContextMiddleware,
    PowerContextScope,
)


agent = create_agent(
    model,
    tools=application_tools,
    middleware=[PowerContextMiddleware()],
    context_schema=PowerContextScope,
)

result = await agent.ainvoke(
    {
        "messages": [{
            "role": "user",
            "content": "What should happen before contract tests?",
        }]
    },
    context=PowerContextScope(
        scope_id="project:powercontext-101",
    ),
)
```

Sync 应用可用 `invoke` / `stream`。Async 应用使用 `ainvoke` / `astream`；在已运行 event loop 中调用 sync API，会让 middleware warning 并跳过 recall/capture，而不是嵌套 loop。

## Recall lifecycle

每个 model request，middleware 读取 latest human text、解析 Scope、调用 `prepare_context`，然后 override 当前 `ModelRequest.system_message`，追加 untrusted block。

Override 不改 agent state，checkpointed `messages` 保持干净。因为每个 model request 都重新 prepare，同 run 中 application tool 显式写 Memory 后，后续 model step 有机会看到新内容。

## 没有 PowerContext tools

Middleware 不注册：

```text
powercontext_search
powercontext_remember
powercontext_context
```

需要时，把 Python Client operation 包成 application tools。不要因为 LangChain 内部使用 LangGraph 就导入 `powercontext-langgraph`；两个 PowerContext package 各自管理 settings、Scope 和 lifecycle。

## Capture 默认关闭

```python
middleware = PowerContextMiddleware(auto_capture=True)
```

成功 run 后，capture 包含 latest user text 和 final non-empty assistant text 或 structured response。它不包含 recalled block、tool output、intermediate tool-calling message，也不捕获没有 final response 的 aborted run。

Capture 创建 Source，不创建 Memory，也不 flush。Scheduler 或显式 `flush_memory` 负责 extraction。当前 middleware 不承诺完整 secret redaction，bounded content 仍可能敏感。

## Scope 与设置

```text
POWERCONTEXT_LANGCHAIN_BASE_URL
POWERCONTEXT_LANGCHAIN_TOKEN
POWERCONTEXT_LANGCHAIN_SCOPE_ID
POWERCONTEXT_LANGCHAIN_TIMEOUT
POWERCONTEXT_LANGCHAIN_MAX_BYTES
```

`TOKEN` 是裸值。Scope precedence 是 per-invocation Scope/env，然后 normalized network Git remote，否则 missing Scope。没有 local path fallback。

## Failure behavior

Recall 与 capture 是独立 best-effort HTTP path：Server unavailable 或 invalid response 不替换 model output；401/403 只记录一次无 credential error；capture failure 保留成功 result。

Missing Scope/configuration 由 automatic middleware path 跳过。这不代表 explicit application tool mutation 会 fail-open；middleware 本身没有这些 tools。

## 与 LangGraph 对比

| Capability | LangChain | LangGraph |
|---|---:|---:|
| Recall frequency | 每 model request | 按 Scope + message ID/text 缓存 |
| PowerContext tools | 否 | 3 个 |
| Automatic capture | 可选，默认关 | 否 |
| Sync | 是 | 否 |
| Injection | current ModelRequest override | `llm_input_messages` |
| Persisted-state pollution | adapter path 下无 | adapter path 下无 |

## 验证

1. Seed explicit Memory。
2. 捕获 model request，确认有 untrusted block。
3. 检查 returned/checkpointed `messages`，确认没有该 block。
4. 默认运行，确认没有 completed-turn Source。
5. 开启 `auto_capture=True` 成功运行，检查 Source journal，不立即搜索 Memory。
6. Abort tool/model，确认没有 final turn capture。
7. 停止 Server，确认原 model flow 继续。

## 当前不支持

- PowerContext Memory Toolset；
- automatic flush；
- Handoff、Candidate Review、Experience、Skill direct operations；
- failed-run transcript capture；
- PyPI installation。
