这里的 Pydantic AI 运行在 PowerContext Server 内部，负责 schema-bound generation 和独立的 embedding provider。它不会安装 [Pydantic AI Agent adapter](/zh/frameworks/pydantic-ai)，不会给 Agent 增加工具，也不共享 Agent adapter 的生命周期。

<Note>
状态：本页所用上游 revision 的 built-in runtime 已提供这项能力。in-process composition 安装 `powercontext[builtin]`，运行 Server 安装 `powercontext[server]`；要求 Python 3.11 或更高版本。本页没有验证真实 provider 调用、credential 和生产环境 latency。
</Note>

## 选择四种 runtime 状态之一

Generation 和 embedding 都是可选项，彼此独立。无模型 Server 仍有实际用途：explicit Memory 和 FTS 都不依赖 provider。

| 状态 | 配置 | 可用能力 |
|---|---|---|
| 无模型 | 两种 model 都不配置 | Explicit Memory、FTS、typed proposal 与 Review，以及 typed Handoff operation |
| 仅 generation | `generation_model` | Source extraction、Experience incubation/generation、Skill generation、Handoff generation 和可选 Memory reranking |
| 仅 embedding | 完整 embedding profile | Vector/hybrid indexing 与 search；explicit Memory write 仍可用 |
| 两者都有 | generation 加完整 embedding profile | 以上全部能力；两个 provider 仍各自独立失败 |

Generation 不会自动启用 Scheduler。可以手动调用 `flush_memory`，也可以另行配置 `POWERCONTEXT_SERVER_RUNTIME_SCHEDULE_SECONDS`。

## 配置 Server

按运行方式安装其中一个 role。此处 pin 与 [LangGraph](/zh/frameworks/langgraph) / [LangChain](/zh/frameworks/langchain) 页相同，写成完整 commit hash：

```bash
uv add "powercontext[builtin] @ git+https://github.com/oceanbase/powercontext.git@4213d32d672a6fb16e74730eb50b9be6a38bcb10"
uv add "powercontext[server] @ git+https://github.com/oceanbase/powercontext.git@4213d32d672a6fb16e74730eb50b9be6a38bcb10"
```

Server settings 使用 Pydantic AI model string。Credential、base URL 等 provider 专用环境变量由所选 provider 读取。

```bash
export POWERCONTEXT_SERVER_INFERENCE_GENERATION_MODEL="openai:gpt-5.2"
export POWERCONTEXT_SERVER_INFERENCE_GENERATION_TIMEOUT_SECONDS="30"
export POWERCONTEXT_SERVER_INFERENCE_GENERATION_MAX_REQUESTS="2"

export POWERCONTEXT_SERVER_INFERENCE_EMBEDDING_MODEL="openai:text-embedding-3-small"
export POWERCONTEXT_SERVER_INFERENCE_EMBEDDING_PROFILE_ID="openai-text-embedding-3-small-v1"
export POWERCONTEXT_SERVER_INFERENCE_EMBEDDING_DIMENSION="1536"
export POWERCONTEXT_SERVER_INFERENCE_EMBEDDING_NORMALIZATION="unit"
export POWERCONTEXT_SERVER_INFERENCE_EMBEDDING_TIMEOUT_SECONDS="30"
export POWERCONTEXT_SERVER_INFERENCE_EMBEDDING_BATCH_SIZE="10"

uv run powercontext server run
```

`EMBEDDING_MODEL`、`EMBEDDING_PROFILE_ID`、`EMBEDDING_DIMENSION` 必须全部配置或全部省略。配置不完整时，Server 会在启动前拒绝。Profile 属于持久化 vector contract；应先确定 ID、dimension 和 normalization，不要在原 profile 上随意改动。

<Warning>
Model string 只是配置，不代表 provider 已经可用。Readiness 会发送一次很小的真实请求，但本页不保证 provider account、credential、quota、regional endpoint、model dimension 或 latency 符合你的部署要求。
</Warning>

## 直接使用 structured generator

底层 generator 只接受已经构造并打开的 Pydantic AI `Model`，传 model string 会被拒绝。Model 生命周期由 caller 管理。

```python
from pydantic import BaseModel
from pydantic_ai.models import infer_model

from powercontext.builtin.inference.pydantic_ai import PydanticAIStructuredGenerator


class ExtractionInput(BaseModel):
    text: str


class ExtractionOutput(BaseModel):
    summary: str


async def generate_summary() -> ExtractionOutput:
    async with infer_model("openai:gpt-5.2") as model:
        generator = PydanticAIStructuredGenerator(
            model=model,
            instructions="Return a concise factual summary.",
            input_type=ExtractionInput,
            output_type=ExtractionOutput,
        )
        result = await generator.generate(ExtractionInput(text="The client must be regenerated."))
        return result.output
```

Server composition 的接口不同：`InferenceConfig.generation_model` 接受 model string，在 runtime 存活期间打开 provider model，复用于各条 generation pipeline，并随 runtime 一起关闭。

## 跟踪 execution flow

### Generation flow

```text
model string
→ Server opens one provider Model
→ schema-bound PydanticAIStructuredGenerator
→ extraction / incubation / generation / Handoff / optional rerank pipeline
→ domain validation and evidence checks
→ explicit durable write or Candidate Review boundary
```

Pydantic AI 先校验声明的 output schema，但这只是第一层检查。生成数据进入权威状态前，PowerContext 还会校验 domain rule、evidence reference、current version 和其他 invariant。生成的 Experience 与 Skill 仍要经过 Candidate Review；structured output 不等于批准。

### Embedding flow

```text
embedding model + profile ID + dimension
→ Server opens the provider and Embedder
→ bounded document batches
→ verify input type, order, count, dimension, normalization, and finite values
→ best-effort write projection or vector/hybrid query
```

Generation 和 embedding 不会互相 fallback，也没有跨 provider fallback。一个正常时，另一个仍可能 degraded。

## 理解 search 与 write failure

| 路径 | Provider failure 行为 | 权威数据 |
|---|---|---|
| `mode="auto"` search | query embedding 暂时失败时，如果 FTS 可用，可以回退到 FTS | 不改变持久状态 |
| `mode="vector"` 或 `mode="hybrid"` search | 返回错误，不会静默改用 FTS | 不改变持久状态 |
| write-time projection embedding | best effort；projection 失败不会丢弃已提交的 Memory | Memory 仍是权威数据，也可由 FTS 找到 |
| generation-backed operation | timeout 或 unavailable 会返回给 operation | invalid 或缺失的生成结果不会被当成成功写入 |

Provider timeout 和 temporary unavailable 会映射为 PowerContext inference error，并由 Server 返回 HTTP 503。重排 embedding、vector 数量或 dimension 错误、非有限值等 invalid output 会被拒绝，不会写入 index。

<Warning>
FTS fallback 成功不能证明 vector search 正常。验证 embedding 时，应发起显式 vector request，并要求 source-linked hit 的 `matched_by` 包含 `vector`。
</Warning>

## 准确解读 readiness

配置 generation 或 embedding 后，会分别增加 non-blocking readiness probe。Inference probe 失败时是 HTTP 200 的 `degraded`，不是 `not_ready`。Runtime 或 database failure 才是 blocking failure，会返回 HTTP 503 的 `not_ready`。

```bash
powercontext ready
powercontext capabilities
```

Server degraded 时，不依赖故障 provider 的 database-backed operation 仍可执行；需要该 provider 的 operation 可能返回 503。

Readiness 只检查当时是否可调用。它不验证生产 quota、pipeline 使用的每一种 schema、持续并发、数据质量或完整的 end-to-end latency。

## 设定 privacy 与 Scope 边界

Provider 会收到 operation 的序列化输入。根据 pipeline 不同，内容可能包括 Source、Memory candidate、query、Handoff evidence 或 Candidate generation evidence。Provider usage 会记录 request/token 计数；启用 instrumentation 后还可能发出 inference span。发送敏感项目内容前，应先确认 provider 的 data handling 和 tracing 配置。

Scope 仍只负责选择 PowerContext 数据。它不能阻止已选内容离开 Server 发往配置的 model，不能证明用户身份、授予 model 权限或批准生成内容。如果 provider 不应看到某个 secret，就不要把它放进 Source 或 Memory。

## 当前不支持或尚未验证

| 项目 | 状态 |
|---|---|
| Pydantic AI Agent tool 或 lifecycle hook | **Unsupported**；使用独立的 Agent adapter |
| generation-to-embedding failover 或跨 provider failover | **Unsupported** |
| 显式 vector/hybrid search 静默 fallback | **Unsupported** |
| 用 schema validation 代替 domain invariant 或 Review | **Unsupported** |
| 真实 provider credential、quota、regional endpoint 和 latency | **Not validated**；本页未做真实 provider 验证 |
| generation 配置自动启用 Scheduler | **Unsupported**；需单独配置 scheduling |

## 完成检查

依赖 inference 前，确认：

- 已有意选择四种状态之一；
- 三个必填 embedding 字段全部设置或全部省略；
- `powercontext ready` 能正确区分 `ready`、`degraded` 和 `not_ready`；
- `powercontext capabilities` 只列出实际配置的 search 与 generation capability；
- 显式 vector 验证失败时错误可见，不会被误认为 FTS fallback；
- provider privacy、tracing、retention 设置适合各 pipeline 发送的数据；
- schema validation 后仍保留 downstream domain validation 与 Candidate Review。
