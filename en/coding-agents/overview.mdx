The five hosts connect to one Server but do not share one Hook API. Their common layer is the domain contract: resolve Scope, prepare temporary context, capture Source independently, and put explicit writes behind host permissions.

## Common execution flow

```text
host event
→ resolve Scope
→ prepare bounded untrusted context
→ inject through host-specific channel
→ run model
→ optionally capture Source / flush
→ explicit tools under host permission
```

## Capability matrix

| Capability | Codex | Claude Code | DSH | OpenCode | Pi |
|---|---|---|---|---|---|
| Automatic event | `UserPromptSubmit` | `UserPromptSubmit` | `agent/pre-step` | `chat.message` + transform | `before_agent_start` |
| Injection | additional context | `additionalContext` | plugin message | exact-turn message transform | system prompt |
| Prompt capture | Yes | Yes | user-originated batch | Yes, filter secret-like prompt | Yes, filter secret/size |
| Final response capture | No | No | No | No | No |
| Explicit interface | MCP | MCP | native HTTP tools | native HTTP tools | native tools + `/pc` |
| Handoff | MCP + Skill | MCP + Skill | curated HTTP tools | curated HTTP tools | native tools |
| Permission | Host-gated | Host-gated | pre-execute `ask` | `context.ask` | interactive confirm; deny without UI |
| Managed Skill export | Supported | Supported | Unsupported | Unsupported | Unsupported |
| Real-host E2E | Not validated | Not validated | Not validated | Supported | package load only; full chain Not validated |

A bundled `project-context` Skill is guidance shipped by an integration. It does not prove managed Skill export support.

## Setup and doctor

```bash
powercontext setup <host> \
  --source oceanbase/powercontext \
  --ref master

powercontext doctor <host>
```

Setup never starts the Server. Doctor is a bounded install/activation check. It is not E2E, and it does not prove live recall, permission UI, or cross-session behavior. Each host page states what that host actually checks.

## Automatic and explicit paths

Automatic recall/capture is a helper path. Server failure usually fail-open. Explicit Memory, Handoff, Review, or export must not pretend success.

Do not copy one host's permission model onto another. Pi refuses durable write without UI. DSH and OpenCode go through the host permission API. Codex/Claude Code no-UI refuse behavior is **Not validated**.

## Choose a path

- Need Hook + MCP + project Skill: Codex or Claude Code.
- Need pre-step and curated HTTP tools: DSH.
- Need exact-turn transient cache and real-host E2E: OpenCode.
- Need boundary flush and no-UI fail-closed: Pi.
