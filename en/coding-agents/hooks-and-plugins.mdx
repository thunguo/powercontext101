A reliable adapter is more than one API call before a prompt. It must fit host events, prevent stale context, protect credentials, and separate automatic helpers from explicit mutations.

## Adapter contract

```text
PromptEvent
→ ScopeResolver
→ PreparedContextProvider
→ schema / size validation
→ TransientInjector
→ SourceCapture
→ optional FlushCoordinator
→ ToolSurface + PermissionGate
→ content-free Diagnostics
```

## Five event models

| Host | Preparation timing | Injection channel |
|---|---|---|
| Codex | short-process `UserPromptSubmit` | hook stdout additional context |
| Claude Code | `UserPromptSubmit` | JSON `additionalContext` |
| DSH | `agent/pre-step` middleware | plugin message after downstream decision |
| OpenCode | prepare on `chat.message`, inject on message transform | `(sessionID,messageID)` exact-turn cache |
| Pi | `before_agent_start` | returned `systemPrompt` augmentation |

Do not copy one host's Stop, transcript, or permission assumptions onto another.

## Security contract

Automatic path tests must cover:

- Server down: the original task continues;
- 401/403 vs empty are distinguishable;
- unknown schema is not injected;
- oversized response / timeout are bounded;
- redirect does not leak Authorization (promise this only where the implementation explicitly refuses);
- capture failure does not delete valid recall;
- stale turn context does not enter a new turn;
- diagnostics contain no prompt, Scope, content, or token.

Explicit mutation must fail visibly and go through host permission. Candidate approval must not be silently opened as a normal model tool.

## Capture is not Memory

```text
prompt capture
→ Source position
→ optional flush / scheduler
→ extraction candidate
→ Memory commit or no-op
```

Adapter docs must state the capture scope: user prompt only, full visible turn, or no capture at all. They must also state the secret and size policy.

## Setup and doctor contract

A new host installer must at least:

- gate versions;
- install idempotently and preserve non-owned config;
- mark ownership and reject overwriting foreign files;
- support rollback or an explicit partial-failure state;
- distinguish plugin installed, host activated, and Server running;
- provide bounded doctor and a real host activation probe.

## No unified HostAdapter SDK

The repository already has reusable helpers, but it has no unified `HostAdapter` abstraction:

- `powercontext.transport` and loopback vectors;
- Codex/Claude prepared-context parser;
- host-specific Scope normalization;
- Pi pending Source flusher;
- DSH generated operation table;
- Codex/Claude Skill projection;
- `hosts.py` setup/doctor catalog.

Reuse the contracts and tests. Do not pretend a unified SDK already exists.
