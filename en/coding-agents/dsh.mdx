<Warning>
DSH has no formal minimum host version. `test_dsh_http_chain.py` verifies the HTTP contract, not a full real host-process E2E; the status is **Not validated**. Mutations return `ask` from `tools/pre-execute` and are **Host-gated**. Managed Skill export is **Unsupported**.
</Warning>

The DSH integration is not an MCP plugin. It recalls and captures in `agent/pre-step`, registers curated `pc_*` HTTP tools, and exposes human `/pc` commands. Setup runs `dsh plugin --profile web add` and does not start the Server.

For the full install, use the Configure DeepSeek Harness how-to in the [official docs](https://oceanbase.github.io/powercontext/). This page covers the PowerContext 101 verification contract.

## Install and activate

Confirm the web profile exists, then start the Server:

```bash
powercontext server run
```

Install the built plugin:

```bash
powercontext setup dsh --source oceanbase/powercontext --ref master

powercontext doctor
powercontext doctor dsh
```

Setup requires a built `integrations/dsh/plugins/powercontext/lib/index.js`. It passes that directory to `dsh plugin --profile web add` and creates the PowerContext user data directory. A usable checkout for the same ref is reused; a broken checkout is replaced. Setup does not start the Server.

`doctor dsh` checks that `dsh` is on PATH and looks for the exact plugin id `powercontext-dsh` in `--profile web --dump-config`. The package name alone is not enough. It does not contact the Server or test recall.

After setup, open a new `dsh web` session.

## Configuration defaults

Environment variables can override the connection and capture flags. `timeoutMs`, `requestTimeoutMs`, `maxBytes`, and `flushMaxCalls` are plugin patch settings, not environment variables.

| Key | Default | Meaning |
|---|---|---|
| `POWERCONTEXT_DSH_BASE_URL` | `http://127.0.0.1:8000` | Running Server |
| `POWERCONTEXT_DSH_SCOPE_ID` | unset | Explicit Scope; required when the session has no workspace cwd |
| `POWERCONTEXT_DSH_AUTHORIZATION` | unset | Complete Authorization header |
| `POWERCONTEXT_DSH_CAPTURE_PROMPTS` | `true` | Capture user-originated prompt text |
| `POWERCONTEXT_DSH_FLUSH_ON_CAPTURE` | `false` | Test-only flush |
| `maxBytes` | `8000` | Recall budget, clamped to `512–32768` |
| `timeoutMs` | `4000` | Total pre-step budget |
| `requestTimeoutMs` | `1000` | Per-request HTTP timeout |

Do not put the token in the patch file or the Server URL. Disable capture when the current work must not become Source evidence:

```bash
export POWERCONTEXT_DSH_CAPTURE_PROMPTS=false
dsh web
```

## Minimal verification

```bash
powercontext doctor
powercontext ready
powercontext capabilities
```

Save the decision in DSH:

```text
Use PowerContext pc_remember to store this decision:
after changing the OpenAPI contract, regenerate the client and inspect the diff.
Return the Memory Citation. Do not store secrets.
```

`pc_remember` first triggers host permission `ask`. After approval it should return a Memory Citation. You can use `/pc` commands for read-only checks.

Ask a new request or open a new session:

```text
What should happen after the OpenAPI contract changes?
```

When automatic recall succeeds, the plugin appends a plugin message only after downstream decides to `enter` the model. That message starts with `PowerContext host-supplied context` and includes a Citation. A non-enter downstream result must not be replaced.

## Scope resolution

DSH resolves Scope in this order:

1. A nonempty `POWERCONTEXT_DSH_SCOPE_ID`.
2. The normalized Git remote on the session workspace cwd, written as `git:...`.
3. A `local:<sha256>` identifier for that same workspace.

Without a workspace cwd, the automatic path skips work and explicit tools return a stable unscoped state: `No project workspace on this session. Set scopeId or open a workspace.` The plugin does not fall back to the Harness process directory.

DSH does not read the Codex / Claude Code Workstream binding.

## Automatic path and explicit tools

```text
agent/pre-step
→ all text blocks form recall query
→ user-originated blocks form capture content
→ resolve workspace Scope
→ prepare and capture independently
→ await next() exactly once
→ only when downstream enters model, append plugin message
```

The full batch improves recall, while Source capture remains user-only. `next()` must run exactly once. Server, validation, or wrapping failure does not replace the downstream result.

The explicit surface covers Memory, Handoff, Experience / Skill generation, and read-only Candidate operations. Dangerous and admin operations are not registered. Named mutation returns `ask` from `tools/pre-execute`, leaving the decision to host permission UI. Candidate approve / reject / revise is not an ordinary model tool; use human `/pc review` or another controlled surface.

The bundled Skill is guidance only. DSH is not a managed Skill export target.

## Negative checks

- Stop the Server, then ask a normal coding question. The agent should continue.
- With the Server still down, run `pc_remember`. Failure must stay visible and must not look like an empty success.
- Permission deny: the mutation must not run.
- Missing cwd: the automatic path skips or returns unscoped and must not guess the process directory.
- Downstream is not `enter`: no plugin message is injected.
- Approval tools must stay off the model surface.

## Current limits

- A real DSH host-process E2E is **Not validated**. The HTTP-chain test is not a full host.
- No formal minimum DSH version is declared.
- Managed Skill export is **Unsupported**.
- Plugin load still requires DeepSeek Harness peer modules.
- Automatic extraction needs a generation model; explicit Memory does not.

## Completion checklist

- `doctor dsh` sees id `powercontext-dsh` in dump-config.
- Server health, readiness, and capabilities were checked separately.
- A new request can recall the OpenAPI decision you saved explicitly, and the Citation appears in the plugin message after enter.
- `next()` runs exactly once; a non-enter path receives no injection.
- Ordinary coding continues when automatic recall fails.
- Explicit Memory or Handoff failure is visible in DSH.
- Mutation triggers `ask`; approve / reject never entered the model tools.
- You did not describe the HTTP-chain test as a real host E2E.
