Source install only: `powercontext-langchain==0.0.1` is not published to PyPI. The documented Git URL follows mutable `master`, and the focused package test does not exercise that VCS installation path. Reproducibility is **Not validated**; pin a reviewed commit and its dependencies.

`PowerContextMiddleware` integrates with LangChain `create_agent`. It supports sync and async execution, changes only the current model request, and optionally captures a completed turn as Source evidence. It has no adapter-owned PowerContext tools.

## Minimum use

```python
from langchain.agents import create_agent
from powercontext_langchain import PowerContextMiddleware, PowerContextScope

agent = create_agent(
    model,
    tools=application_tools,
    middleware=[PowerContextMiddleware()],
    context_schema=PowerContextScope,
)

result = await agent.ainvoke(
    {
        "messages": [
            {
                "role": "user",
                "content": "What should happen after changing the OpenAPI contract?",
            }
        ]
    },
    context=PowerContextScope(scope_id="project:powercontext-101"),
)
```

The same middleware supports `invoke` and `stream` in a synchronous application, and `ainvoke` and `astream` in an async application.

<Warning>
Do not call a synchronous agent method from an already running event loop. The host still runs, but PowerContext recall and capture are skipped and the middleware logs one warning. Use the async agent API there.
</Warning>

## Execution flow

```text
before every model request
→ read latest human message
→ resolve per-invocation Scope and connection settings
→ prepare_context(query <= 8192 chars, max_bytes)
→ append an untrusted block to this ModelRequest.system_message
→ call model without changing agent state
→ after successful agent completion, optionally capture latest user + final response
```

Recall runs before every model request. It is not once per run like the Pydantic AI Capability, and it is not once per human turn with a cross-step cache like LangGraph. A later model step can therefore see Memory written earlier in the same run by an application-owned tool.

The middleware overrides only the current `ModelRequest.system_message`. It never writes the recalled block to framework state or a checkpointer. The existing system message remains first; the untrusted context block is appended for that one request.

## Capture is opt-in

Enable capture only after deciding that user and final model content may be stored durably:

```python
middleware = PowerContextMiddleware(auto_capture=True)
```

`auto_capture` defaults to `False`. `after_agent` or `aafter_agent` captures only after successful completion, using the latest non-empty user message plus either a serializable `structured_response` or the final non-empty assistant response.

| Included | Excluded |
|---|---|
| Latest user text | Tool output |
| Final assistant text | Intermediate tool-calling messages |
| Serializable `structured_response` | Recalled PowerContext block |
| Truncation metadata | Aborted run or run without a final response |

The combined Source payload has a separate 200,000 Python-character ceiling. The adapter divides the available budget between user and assistant text and records truncation flags.

<Note>
Capture creates a Source. It does not create or approve Memory, and the middleware does not flush. Server extraction may run later through the scheduler or an explicit Client operation, and may produce a no-op.
</Note>

## Scope and configuration

Pass `PowerContextScope` on each invocation when one agent serves more than one tenant. Per-invocation values for Scope, base URL, token, and timeout override environment values.

```python
scope = PowerContextScope(
    scope_id="tenant:acme:project:api",
    base_url="https://context.example.com",
    token="opaque-server-token",
    timeout=8.0,
)

result = await agent.ainvoke(state, context=scope)
```

| Setting | Default |
|---|---:|
| `POWERCONTEXT_LANGCHAIN_BASE_URL` | `http://127.0.0.1:8000` |
| `POWERCONTEXT_LANGCHAIN_TOKEN` | unset |
| `POWERCONTEXT_LANGCHAIN_SCOPE_ID` | derived or error |
| `POWERCONTEXT_LANGCHAIN_TIMEOUT` | `10` seconds |
| `POWERCONTEXT_LANGCHAIN_MAX_BYTES` | `8000`; accepted range `512`–`32768` bytes |

Scope precedence is:

```text
PowerContextScope(scope_id=...)
→ POWERCONTEXT_LANGCHAIN_SCOPE_ID
→ normalized network Git origin
→ MissingScopeError
```

There is no local-path fallback. HTTP(S), SSH, Git, and SCP-like network remotes are normalized without credentials. An overlong explicit Scope is replaced by a bounded SHA-256 identifier.

The token convention is a bare token without `Bearer `. The adapter does not strictly validate that syntax. The shared `PowerContextClient` rejects plaintext HTTP to non-loopback hosts unless the caller supplies an explicitly trusted transport.

## Failure, privacy, and Scope boundary

Automatic recall and capture are independent fail-open paths. Missing Scope, malformed configuration, request validation, authentication failures, timeouts, Server failures, or an unserializable structured response do not replace the model result or abort the host run. HTTP 401/403 is logged as configuration trouble, not treated as empty Memory.

The middleware does not add explicit PowerContext tools. If the application wraps Python Client mutations as its own tools, their failure contract and permissions belong to the application; automatic fail-open behavior does not make those mutations successful.

<Warning>
Recall can contain old user or model text. Treat it as untrusted evidence, not an instruction, identity proof, or permission grant. Scope chooses a data partition; derive it from an authenticated tenant/project mapping when isolation matters.
</Warning>

Capture can store ordinary prompts, code, business data, and final model output. This adapter does not promise comprehensive secret redaction. Keep `auto_capture=False` until the application has content filtering, consent, retention, and deletion rules. Tool output is excluded, but that alone is not a privacy policy.

## Compare with LangGraph

| Capability | LangChain | LangGraph |
|---|---|---|
| Recall frequency | Every model request | Once per human turn, cached across model steps |
| Adapter-owned tools | None | Three Memory tools |
| Automatic capture | Optional completed-turn Source; default off | None |
| Invocation | Sync and async | Async only |
| Injection channel | Current `ModelRequest.system_message` | Ephemeral `llm_input_messages` |
| Framework state mutation | None | Recall does not mutate persisted `messages` |
| Flush | None | None |

## Completion checklist

- The Server runs separately, and the source-installed middleware is pinned to a reviewed commit.
- Sync code runs outside an event loop; async code uses `ainvoke` or `astream`.
- A captured model request contains the untrusted recall block, while returned and checkpointed state does not.
- Tests expect recall before every model request, not once per run or once per turn.
- Every invocation receives the intended Scope; a cross-Scope negative test proves tenant isolation.
- `MAX_BYTES` is between 512 and 32,768, queries over 8,192 characters are expected to be clamped, and remote transport uses HTTPS.
- With the Server unavailable, the model flow continues and 401/403 remains distinguishable from empty Memory.
- `auto_capture` remains off unless completed-turn storage has an explicit privacy and retention policy.
- When capture is enabled, checks inspect Source rather than assuming Memory or flush.
- Unsupported and Not validated items remain distinct in deployment notes.
