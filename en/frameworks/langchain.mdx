<Note>
Source install only: `powercontext-langchain` is not published to PyPI. It is an independent middleware package and does not depend on `powercontext-langgraph`.
</Note>

`PowerContextMiddleware` integrates with LangChain `create_agent`. It prepares before every model request and changes only that request, not agent state or the checkpointer. It provides no PowerContext Memory tools.

## Install

```bash
uv tool install --force \
  "powercontext[cli,server] @ git+https://github.com/oceanbase/powercontext.git@master"

uv pip install \
  "powercontext-langchain @ git+https://github.com/oceanbase/powercontext.git@master#subdirectory=integrations/langchain"

powercontext server run
```

The current package requires LangChain 1.3 or later. Pin a tested commit for reproducible deployment.

## Minimal integration

```python
from langchain.agents import create_agent
from powercontext_langchain import (
    PowerContextMiddleware,
    PowerContextScope,
)


agent = create_agent(
    model,
    tools=application_tools,
    middleware=[PowerContextMiddleware()],
    context_schema=PowerContextScope,
)

result = await agent.ainvoke(
    {
        "messages": [{
            "role": "user",
            "content": "What should happen before contract tests?",
        }]
    },
    context=PowerContextScope(
        scope_id="project:powercontext-101",
    ),
)
```

Sync applications may use `invoke` / `stream`. Async applications use `ainvoke` / `astream`; calling sync API inside a running event loop makes the middleware warn and skip recall/capture rather than nest loops.

## Recall lifecycle

For every model request, middleware reads latest human text, resolves Scope, calls `prepare_context`, and overrides current `ModelRequest.system_message` with an added untrusted block.

The override does not change agent state. Checkpointed `messages` remain clean. Because prepare runs on each model request, a later model step can see Memory explicitly written by an application tool in the same run.

## No PowerContext tools

Middleware does not register:

```text
powercontext_search
powercontext_remember
powercontext_context
```

Wrap Python Client operations as application tools if needed. Do not import `powercontext-langgraph` simply because LangChain itself uses LangGraph internally; the PowerContext packages own separate settings, Scope, and lifecycle.

## Capture is opt-in

```python
middleware = PowerContextMiddleware(auto_capture=True)
```

After a successful run, capture contains latest user text and final non-empty assistant text or structured response. It excludes recalled blocks, tool output, intermediate tool-calling messages, and aborted runs without final response.

Capture creates Source, not Memory, and performs no flush. Scheduler or explicit `flush_memory` owns extraction. Current middleware does not promise complete secret redaction, so bounded content can still be sensitive.

## Scope and settings

```text
POWERCONTEXT_LANGCHAIN_BASE_URL
POWERCONTEXT_LANGCHAIN_TOKEN
POWERCONTEXT_LANGCHAIN_SCOPE_ID
POWERCONTEXT_LANGCHAIN_TIMEOUT
POWERCONTEXT_LANGCHAIN_MAX_BYTES
```

`TOKEN` is bare. Scope precedence is per-invocation Scope/env, then normalized network Git remote, otherwise missing Scope. There is no local path fallback.

## Failure behavior

Recall and capture are independent best-effort HTTP paths: Server unavailable or invalid response does not replace model output; 401/403 logs one credential-free error; capture failure preserves successful result.

Missing Scope/configuration is skipped by the automatic middleware path. This says nothing about explicit application-tool mutations; the middleware provides none.

## Compare with LangGraph

| Capability | LangChain | LangGraph |
|---|---:|---:|
| Recall frequency | Every model request | Cache by Scope + message ID/text |
| PowerContext tools | No | 3 |
| Automatic capture | Optional, off by default | No |
| Sync | Yes | No |
| Injection | Current ModelRequest override | `llm_input_messages` |
| Persisted-state pollution | No under adapter path | No under adapter path |

## Verify

1. Seed explicit Memory.
2. Capture model request and confirm untrusted block exists.
3. Inspect returned/checkpointed `messages` and confirm it does not.
4. Run with default capture and confirm no completed-turn Source.
5. Enable `auto_capture=True`, run successfully, then inspect Source journal rather than Memory search.
6. Abort a tool/model call and confirm no final turn capture.
7. Stop Server and confirm original model flow continues.

## Unsupported

- PowerContext Memory Toolset;
- automatic flush;
- direct Handoff, Candidate Review, Experience, or Skill operations;
- failed-run transcript capture;
- PyPI installation.

Continue with [Framework tricks](/en/frameworks/tricks).
