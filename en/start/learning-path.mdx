You do not need to read the whole site first. Separate a few objects, then pick the path that matches the work in front of you.

Do not walk several paths at once. A local API loop, a Python framework, and an agent plugin answer different questions. Finish one, then decide whether you need the next.

<Steps titleSize="h3">
  <Step title="Separate the objects first" icon="brain">
    Start with the [mental model overview](/en/mental-model/overview), then read [Scope](/en/mental-model/scope) and [fail-open](/en/mental-model/fail-open). At minimum, keep <Tooltip headline="Source" tip="Records what happened. Capture does not write durable knowledge." cta="Read Source" href="/en/mental-model/source">Source</Tooltip>, <Tooltip headline="Memory" tip="Selected project knowledge that should matter later." cta="Read Memory" href="/en/mental-model/memory">Memory</Tooltip>, <Tooltip headline="PreparedContext" tip="A bounded view for one request. It includes Citations and is not a durable asset." cta="Read the mental model overview" href="/en/mental-model/overview">PreparedContext</Tooltip>, and <Tooltip headline="Handoff" tip="Packages the current objective, verified progress, blockers, and next action. It stays temporary until an explicit commit." cta="Read Handoff" href="/en/mental-model/handoff">Handoff</Tooltip> apart.
  </Step>
  <Step title="Start a local Server" icon="server">
    Follow [Install and run the Server](/en/basic-usage/install-and-run) with the minimum setup. Writing Memory and using full-text search do not need an inference provider.
  </Step>
  <Step title="Choose one path" icon="route">
    Pick one goal below. Finish that loop before comparing other frameworks or agents.
  </Step>
  <Step title="Use official docs for details" icon="book-open">
    For install options, interface details, and deployment, use the latest published [official docs](https://oceanbase.github.io/powercontext/). PowerContext 101 helps you choose a path and verify the result.
  </Step>
</Steps>

<Warning>
The documented installation targets are macOS and Linux with Python 3.11 or later. This tutorial does not provide an unverified Windows workaround.
</Warning>

## Choose by your goal

<Tabs>
  <Tab title="I am new to PowerContext">
    Read in this order:

    1. [Mental model overview](/en/mental-model/overview)
    2. [Scope](/en/mental-model/scope)
    3. [fail-open](/en/mental-model/fail-open)
    4. [Install and run the Server](/en/basic-usage/install-and-run)
    5. [API tour](/en/basic-usage/api-tour)

    How do you know it worked? Follow steps 4 and 5 above. Start the local Server on [Install and run the Server](/en/basic-usage/install-and-run), then open the [API tour](/en/basic-usage/api-tour) and run the script to write one Memory.

    The terminal should show three things: `search_memory` hits that Memory, `prepare_context` returns non-empty content, and the result includes a Citation. If it does not match, start with [Troubleshooting](/en/start/troubleshooting).

    Skip framework pages, agent-host pages, and the later Source / Handoff tutorials for now.

    If you want a little more (optional)

    If the objects still blur, read [Source](/en/mental-model/source), [Memory](/en/mental-model/memory), [Handoff](/en/mental-model/handoff), and [Experience and Skill](/en/mental-model/experience-and-skill). After the first loop, continue only if you need [Source and Memory](/en/basic-usage/source-and-memory), the [Handoff loop](/en/basic-usage/handoff-loop), or [Experience / Skill Review](/en/basic-usage/experience-skill-review). To connect an MCP client to the same data, read [Connect with MCP](/en/basic-usage/mcp). To check active and inactive counts for the same Scope, read [Verify Scope statistics in the Dashboard](/en/basic-usage/dashboard). Read Memory text through the Client, HTTP, or MCP.
  </Tab>
  <Tab title="I write Python agents">
    Separate the objects, then [install and run the Server](/en/basic-usage/install-and-run), finish the [API tour](/en/basic-usage/api-tour), and open [Framework integration](/en/frameworks/overview).

    How do you know it worked? First run the [API tour](/en/basic-usage/api-tour) script until you see a write, a search hit, and a cited `prepare_context` result. Then open the [framework integration overview](/en/frameworks/overview) and connect that same Memory in the LangGraph or LangChain page. A new session should still find the conclusion you just wrote.

    For a first integration, choose LangGraph or LangChain. Do not start with Server inference or a Preview adapter. The Pydantic AI Agent adapter is **Preview** and has no working standalone install path, so it is not a first integration.

    If you only need automatic recall, you can leave Handoff and Skill for later.

    If you want a little more (optional)

    After LangGraph or LangChain works, read [framework tricks](/en/frameworks/tricks). Add [Source and Memory](/en/basic-usage/source-and-memory), the [Handoff loop](/en/basic-usage/handoff-loop), and [Experience / Skill Review](/en/basic-usage/experience-skill-review) only when you need extraction, Handoff, or Skill. Read Server inference and the Preview adapter later, not first.
  </Tab>
  <Tab title="I use Hermes / OpenClaw">
    Separate the objects, then [install and run the Server](/en/basic-usage/install-and-run). Open the [common agents overview](/en/common-agents/overview), then [Hermes](/en/common-agents/hermes) or [OpenClaw](/en/common-agents/openclaw).

    How do you know it worked? Open the [Hermes](/en/common-agents/hermes) or [OpenClaw](/en/common-agents/openclaw) page and finish its install plus `powercontext doctor <host>`. A passing `doctor` only means the plugin is installed. Open a new session and ask for the Memory you stored explicitly. If the session can find it, the path works.

    After `powercontext setup hermes`, run `hermes memory setup` and select PowerContext. For OpenClaw, confirm that the plugin owns the Memory slot. WorkBuddy uses its own `setup workbuddy` path. The portable Agent Plugin has no setup command; load its package directory and verify explicit MCP operations. Installation, credentials, and durable writes still require your authorization.

    If you want a little more (optional)

    After recall works, read [Handoff](/en/mental-model/handoff), the [Handoff loop](/en/basic-usage/handoff-loop), and [Experience / Skill Review](/en/basic-usage/experience-skill-review). [Agent self-extension](/en/common-agents/agent-self-extension) covers managed Skill export only. Hermes and OpenClaw cannot export; switch to Codex or Claude Code for that step.
  </Tab>
  <Tab title="I use a coding agent">

    Choose Codex, Claude Code, DSH, OpenCode, or Pi. They share the same Server. Their lifecycles, injection points, and permission checks differ.

    How do you know it worked? Open the [coding agents overview](/en/coding-agents/overview), pick a host, and follow that page's install and checks. After you stop the Server, ordinary coding should still continue. If an explicit Memory write or Handoff commit fails, the page or terminal must show the error. Each host page rewrites these steps with its own tools.

    If you want a little more (optional)

    After the host page works, read [Hooks and plugins](/en/coding-agents/hooks-and-plugins) and [Extend hooks](/en/coding-agents/extend-hooks). Use [Source](/en/mental-model/source), [Memory](/en/mental-model/memory), [Handoff](/en/mental-model/handoff), and [Experience and Skill](/en/mental-model/experience-and-skill) for object detail. The extra runnable pages are [Source and Memory](/en/basic-usage/source-and-memory), the [Handoff loop](/en/basic-usage/handoff-loop), and [Experience / Skill Review](/en/basic-usage/experience-skill-review).
  </Tab>
  <Tab title="I am building an integration">

## Check it with the same question

Whatever path you pick, use this to see if it actually works. On the first-contact path, do it in the [API tour](/en/basic-usage/api-tour). After you connect an agent, redo it on that host page with its own tools.

You just wrote a conclusion you will need later. Can the next request find it?

1. Write it explicitly in a fixed Scope.
2. Ask again in a new request or session.
3. Check that the recalled content has a Citation and enters only this model request.
4. Stop the Server and ask again. Automatic recall may fail. The original task should continue.
5. Try one explicit write. The failure must be visible. It cannot pretend the save succeeded.

Do not treat this list as a checkbox by itself. If the symptom does not match, start with [Troubleshooting](/en/start/troubleshooting).

<Tip>
If PowerContext fails while automatically fetching context, keep working. If you explicitly write a Memory, commit a Handoff, approve a proposal, or export a Skill, you must see the failure. Read [fail-open](/en/mental-model/fail-open) for the full rule.
</Tip>
