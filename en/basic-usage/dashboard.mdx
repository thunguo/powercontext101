---
title: "Verify Scope statistics in the Dashboard"
description: "Configure the same Scope as the Client and verify active, inactive, and total statistics."
---

The Dashboard is the Server's read-only statistics interface. It stores no second copy of data and does not discover every Scope automatically. More importantly, the current UI does not display Memory text or Citations. It can confirm that a Scope contains data, show active/inactive/total Memory counts, and expose Source, Candidate, usage, and recall statistics.

That changes the goal. The API tour retires its example Memory before finishing, so the Dashboard should not show “the Memory you just wrote” as active content. The correct result for that Scope is `total=1`, `active=0`, and `inactive=1`.

## Configure the exact Scope

The API tour prints a UUID-bearing `scope:` value. Copy the full value. Add it to `.env`:

```bash
POWERCONTEXT_SERVER_DASHBOARD_ENABLED=true
POWERCONTEXT_SERVER_DASHBOARD_SCOPES=[{"scope_id":"PASTE_THE_FULL_SCOPE","display_name":"PowerContext 101 API tour"}]
```

The CLI does not load `.env` implicitly:

```bash
powercontext server run --env-file .env
```

Open:

```text
http://127.0.0.1:8000/
```

Select the configured Scope. Statistics should show one Memory entry, now inactive. The Dashboard reports counts only. To inspect text, use the Python Client with `list_memory_entries(include_inactive=True)` or read the exact Citation.

If the page opens with no Scope options, confirm that the running Server loaded `POWERCONTEXT_SERVER_DASHBOARD_SCOPES`. If the Scope exists but every count is zero, verify that Dashboard and Client use the same database URL or `POWERCONTEXT_HOME`. Changing either the database or Scope produces a similar “missing data” symptom.

<Warning>
Dashboard publication sends an approved managed Skill to a preconfigured target. It is unrelated to this statistics check and is not `powercontext skill export`.
</Warning>

With Bearer authentication enabled, `/` still opens, but Dashboard statistics requests need the Server token. Enter it in the page prompt; never place it in the URL.

The proof of success is statistical agreement between Dashboard and Client for one Scope and database, not visible Memory text. Use Client, HTTP, or MCP for exact content and history.

If the counts still disagree after Scope and database settings match, stop here. Restart the Server with the intended `--env-file`, repeat the API tour against that process, and compare the printed Scope literally. An empty or mismatched Dashboard is a configuration failure, not evidence that Memory was deleted.
